项目、子工作区、分支与工作树

项目是导航和工作上下文

入口可以是单个 Git 仓库、普通目录或多仓库工作区。根目录可以打开终端，也可以选择成员仓库或某个工作树进入更具体的上下文。

项目根目录
├─ 根级终端与共享文件
├─ 成员仓库 → 分支 / Git worktree
└─ 注册子工作区
   ├─ 独立 Git 仓库
   └─ 已链接的 Git worktree

子工作区是一个已登记的目录

服务端保存目录位置、标识和排序。刷新时重新扫描实际存在的独立仓库和 worktree，读取各自分支。Git 仓库继续独立拥有提交、远端、分支及 Git 写操作。

分支是 Git 引用，工作树是磁盘上的检出目录。应用保留之前的分支工作区兼容逻辑，新登记目录允许成员使用不同分支。

桌面启动与原生 IPC
  1. 主进程启动服务端

    Electron 以 Node 模式派生服务端子进程，传入监听配置和内部凭据。独立 Web 部署通过 serve.sh 启动同一个服务端实现。

  2. 界面加载 React

    桌面窗口加载 SPA，经 Preload contextBridge 获取启动信息和受限 IPC。Git、文件和终端数据由服务端接口返回。

  3. 原生动作走 Electron IPC

    剪贴板、窗口和外部应用等能力由主进程执行。Chromium 另运行 Renderer、GPU 和网络 Helper，终端 worker 有独立的生命周期。

Hobgoblin · Electron 主进程
├─ Hobgoblin · Node 服务端
│  └─ Hobgoblin · 终端 worker → Shell / AI CLI
├─ Hobgoblin Helper · GPU
├─ Hobgoblin Helper · 网络
└─ Hobgoblin Helper (Renderer) · React 界面

本次 macOS 实测有 6 个应用进程。加上终端拉起的 2 个 zsh 和 3 个 codex，进程树共 11 个。终端与额外窗口的数量会影响进程数。

工作区、Git 与文件变更
  1. 界面取快照或提交操作

    React 通过 /api/repo 或 /api/workspace 读取分支、工作树、文件和状态，也从这些边界提交相应操作。

  2. 服务端执行

    路由验证请求，业务模块调用本机 Git、文件系统或 SSH 目标。后台 fetch 由服务端调度，同一仓库的网络任务按仓库协调。

  3. 通知其他界面刷新

    /ws/invalidation 通知发生变化的范围，各界面重新请求对应快照。React Query / Zustand 保存本地缓存和界面投影。

Git 路由 · 工作区路由 · 状态同步规则

桌面或 Web 打开交互式终端
  1. 界面连接已有终端或新建

    xterm.js 通过 /ws/terminal 绑定会话。终端上下文确定项目、工作目录以及本机、SSH 或 Windows Shell 目标。

  2. 终端 worker 持有 PTY

    服务端通过 Node 子进程 IPC 转发请求。worker 用 node-pty 打开进程并维护终端会话、控制权和近期输出。

  3. 键盘输入与输出实时传输

    输入和尺寸变化传给 PTY，输出经原连接回到界面。选用 tmux 时，符合恢复条件的会话可重新连接到同一个 tmux 进程。

WebSocket 路由 · Worker IPC · PTY 启动

桌面和 Hob AI 接续后台会话
  1. 选执行目标并发送消息

    新版 Hob AI 用 /api/open/v1，桌面 AI 面板用 /api/agent-sessions。会话绑定项目、目标目录和 Provider。

  2. 服务端运行 CLI 并写入 SQLite

    同一个 Runtime 保存 prompt、请求 ID 和执行状态，在本地目录或 SSH 主机执行 Codex / Claude。后续轮次使用 Provider 会话 ID 恢复上下文。

  3. 各端读回同一条会话

    客户端轮询状态，检测到进展后读结构化消息。Muse 的专用兼容入口 /api/open/v1/muse 共享后端会话存储。

Android 终端版直接操作远程主机
  1. 手机保存 SSH Host

    Android 终端版在本机管理 SSH Host、项目、保留终端及排序。SSH 身份采用 Android 端的安全存储。

  2. SSHJ 建立远程能力

    应用经 SSH 查询远程路径、Git 项目与工作树，打开远程 PTY 或设置端口转发。

  3. 终端与 tmux 流程

    Termux 组件渲染字节流。tmux 页枚举目标主机支持的会话，并可按原身份重新连接。

项目入口、端口转发与通知
  1. 桌面和编辑器

    hob CLI 把本地路径交给桌面应用打开或导入。文件区域可以预览文件和差异，并将路径和行号传给配置的编辑器。

  2. 远程开发端口

    主应用通过服务端端口转发路由管理 SSH 隧道，Android 终端版使用自己的 SSH 连接管理转发。

  3. Telegram

    服务端将配置启用的终端事件发到 Telegram，支持终端通知和受配置控制的远程终端输入。

代码布局与目前进度

主应用与正式交付

src/main 与 src/preload 管桌面壳，src/web 管 React 界面，src/server 管服务端，src/system 封装系统集成，src/shared 定义共享类型和契约。

发布工作流用根目录代码构建 macOS 和 Windows 安装包，并准备 Linux Server Mode 源码包。原 Android 发布任务构建 android/。

独立平台包

windows/ 是自包含的 Windows 开发和验证工程。android/ 是 SSH 终端版。android-ai/ 是独立 AI 客户端，当前真机版本为 0.1.0 调试包。

当前源码已实现注册子工作区发现、桌面和手机共用后台会话、通用 OpenAPI 与 Muse 兼容入口。
