      会话如何保持一致
      
    
        
  • 打开会话后，两端用 GET /sessions/{sessionId}/status 查状态。运行中约每 1.5 秒查询一次，空闲约每 4 秒。状态或最新轮次变化后才读取完整消息。
    • 
        
  • 发送为异步请求。重试同一次发送沿用 requestId，停止按会话 ID 和轮次 ID 定位。
    • 
        
  • 端内的会话列表按各自周期刷新。手机回到前台会重新读取服务端状态。
    • 
      

    

    

      数据库与保留期限
      
Hob 的数据目录包含 conversation-open-api/conversations.sqlite。它存储后台会话元数据、消息和执行轮次。清理在服务启动时检查，运行中每分钟检查一次，请求读写数据库时也会检查到期记录。当前历史接口一次返回该会话保留期内的完整消息。

      
Codex 可以输出逐行 JSON 事件。当前 Provider 适配读取最终回复并保存到 SQLite。部署版的跨端状态通过 HTTP 轮询获取。

    

    

      客户端边界和当前部署状态
      
手机配置 HTTPS 服务地址和 OpenAPI Key。这次联调环境的 HTTPS 入口通过 Cloudflare Tunnel 转发到 Mac 上的 Hono。

      
Hob AI 是独立包名的 Android 应用。原生 SSH、tmux 终端由旧 Android 应用管理。桌面的 AI 会话入口与终端入口各自访问对应的会话服务。

      
示例步骤使用虚构数据。新构建已验证同一会话能跨端续聊，也已用打包产物验证两个接口能读到同一个注册子工作区。已安装的设备仍待切换到新构建并联调。
