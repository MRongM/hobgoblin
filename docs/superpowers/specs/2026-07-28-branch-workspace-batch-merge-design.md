# 子工作区批量合并设计

**日期**：2026-07-28  
**状态**：已实施

## 背景

现有批量合并把每个成员清单中的 `baseBranch` 同时当作合并目标，并要求该分支已经在现有工作树中检出。这混合了两个独立概念：成员工作树的创建基准与本次合并的目标。成员也可能从不同来源创建，因此创建基准、bootstrap 来源和合并目标之间不应存在隐式绑定。

## 目标

1. 批量合并与成员的 `baseBranch`、工作树 bootstrap 来源、分支创建来源完全解耦。
2. 用户为每个选中的成员工作树显式选择一个本地目标分支；不同仓库可以选择不同名称的分支。
3. 未被任何工作树检出的本地分支同样可选，由服务端使用应用临时工作树执行。
4. 所选成员继续按清单顺序逐个执行，并显示准备、拉取、合并、推送和临时工作树清理进度。
5. 失败后停止且不回滚已经完成的提交或远端写入；重试固定使用首次执行的成员、目标分支和模式。

## 非目标

- 不把本次目标分支写回成员清单或设置默认值。
- 不自动从 `baseBranch`、上游、默认分支或创建来源推断目标分支。
- 不支持远端跟踪引用作为合并目标；目标必须是当前仓库中的本地分支。
- 不并行执行成员，不提供跨仓库事务、自动回滚或命令级百分比。
- 不改变批量提交、批量拉取和批量推送。

## 领域模型

`Branch workspace base branch` 仅表示成员目标分支创建时使用的仓库级基准，并可参与工作树 bootstrap 来源选择；它不是合并目标。

`Branch workspace batch merge target` 是一次批量合并中，为一个成员仓库显式选择的现有本地分支。它是短期交互状态，随计划执行结束而消失。目标分支与成员的目标分支不能相同。

执行输入为非空映射列表：

```ts
interface BranchWorkspaceBatchMergeTargetInput {
  repositoryName: string
  destinationBranch: string
}
```

仓库名称决定成员身份，目标分支决定该成员的合并落点。服务端始终按计划中的成员顺序重排输入，不信任客户端顺序。

## 交互设计

批量合并使用前台弹窗。每行包含：

- 成员复选框；
- 仓库名与成员目标分支；
- 必填的目标分支选择器；
- 当前可执行性或上游状态。

来源工作树干净且至少存在一个可用目标分支的成员默认选中，但目标分支不默认选择。所有选中成员都选定目标分支后，“仅合并”才可执行；“拉取、合并并推送”还要求每个所选目标分支都有可用上游。

目标分支选择器列出除成员目标分支外的所有本地分支：

- 已在干净现有工作树中检出的分支可用；
- 未检出的分支可用，但选择器只呈现目标分支名，不暴露临时工作树等内部执行信息；
- 已在脏工作树中检出的分支禁用；
- 工作树状态不可读或已锁定的应用临时工作树禁用。

批量合并弹窗使用比原布局宽两个尺寸档的桌面宽度，目标分支列获得至少 `16rem` 的空间。触发器与弹出选项不得因内部状态文案挤占分支名；超长分支在弹出选项中完整换行显示。

开始后锁定成员、目标分支和模式。每个成员显示与实际管线一致的步骤：

- 现有工作树，仅合并：`准备 → 合并`；
- 临时工作树，仅合并：`准备 → 合并 → 清理`；
- 现有工作树，远端模式：`准备 → 拉取 → 合并 → 推送`；
- 临时工作树，远端模式：`准备 → 拉取 → 合并 → 推送 → 清理`。

## 计划与校验

合并计划不再读取或验证 `baseBranch`。每个成员计划包含：

- 成员目标分支、目标工作树和目标提交；
- 来源工作树是否干净；
- 可选本地目标分支列表；
- 每个目标分支的工作树状态、上游状态及是否需要应用临时工作树。

成员指纹只绑定成员目标分支的提交和工作树状态，以及可选目标分支的身份集合；目标分支的最新提交和上游状态在执行前重新读取。这样用户确认的是“把此来源分支合并到这个分支”，而不是把操作错误地锁死到一个稍后可能被正常拉取更新的目标提交。

未选择成员的状态变化不阻断批次；成员身份或清单顺序变化仍使计划过期。所选来源分支变化、来源工作树变脏、目标分支删除或目标现有工作树变脏时，在任何 Git 写入前停止。

## 临时工作树安全

若目标分支没有现有工作树，服务端在仓库同级目录下创建名称以 `.hobgoblin-batch-merge-` 开头的应用临时工作树。该前缀已经属于应用临时条目的排除范围，不会被识别成工作区仓库或依赖候选。

临时工作树不运行 repository bootstrap。成功、失败和取消后都尝试强制移除临时工作树，但绝不删除目标分支。合并冲突发生在临时工作树时，不保留隐藏的冲突现场；服务端移除临时工作树并报告冲突。若目标分支原本就在用户现有工作树中，则沿用普通合并语义并保留冲突现场供用户处理。

进程中断遗留的、路径满足本仓库专用临时前缀约束的工作树会在下一次选择该目标时先清理再重建。普通用户工作树永远不会被此清理路径移除。

## 执行与重试

服务端首次执行绑定：

- 模式；
- 按计划排序的成员仓库；
- 每个成员的目标分支。

批次逐成员执行，单成员内部按步骤执行。`completed` 记录完成成员，步骤进度记录已经完成的拉取、合并或推送。失败后相同输入可以重试并跳过已完成写入；改变成员、目标分支或模式会在新写入前被拒绝。

## 状态与分层

- 共享层定义计划、目标映射和严格输入规范化。
- 服务端计划层读取仓库快照并投影目标候选。
- 服务端写路径拥有校验、临时工作树生命周期、顺序执行、取消和失效发布。
- Renderer 只持有弹窗内的选择，并把服务端活动快照投影为进度。
- Git 与 SSH 的本地/远端差异继续由现有 repository backend 隐藏。

不增加全局 store、持久字段、轮询、Electron 专用协议或新的通用 service。

## 测试策略

- 共享协议：接受并规范化成员/目标映射；拒绝空列表、重复成员和非法文本。
- 计划：忽略 `baseBranch` 是否检出；列出除来源外的本地分支；标记现有脏工作树和未检出分支。
- 写路径：按计划顺序使用各自目标；远端模式按所选目标检查上游；重试绑定目标；临时工作树创建与成功/冲突/取消清理。
- Renderer：每个选中成员必须选择目标；提交映射；远端按钮按所选目标计算；锁定与分步骤进度正确。
- 文档与多语言：不再把 base branch 描述为固定合并目标，四种语言键保持一致。
- 全量验证：`bun run typecheck`、`bun run test`、`bun run check:architecture`。

## 架构压力检查结论

- **边界明确**：创建基准是持久成员意图，批量合并目标是一次性命令参数。
- **仓库隔离**：每个成员仍是独立 Git 边界，目标分支只能来自同一仓库。
- **状态所有权**：选择留在组件本地；可执行事实与执行状态由服务端重新验证。
- **故障安全**：普通工作树不被自动删除；只有路径和用途均受控的应用临时工作树可强制清理。
- **可恢复性**：已完成 Git/远端写入不回滚，重试绑定完整目标映射并跳过完成步骤。
- **分层**：未把 Git 命令、SSH 分支或服务端策略泄漏到 Renderer。

不创建 ADR：这是现有子工作区 Git 动作的领域语义修正，未引入跨功能的长期平台决策。
