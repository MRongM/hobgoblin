# 创建工作树依赖开关设计

**日期**：2026-08-03  
**状态**：已确认，授权内联自主实施

## 问题

单仓库“创建新工作树”弹窗当前会在打开时立即读取工作树引导候选，并在存在候选时直接展开依赖来源与选择列表。这使一项可选能力默认占用界面空间，并为不需要带入依赖的创建操作发起无意义预检。

“新建/扩展子工作区”已经使用默认关闭的仓库依赖开关。本次将相同的显式选择语义应用到单仓库创建工作树流程，但不改变子工作区行为。

## 目标

- 在单仓库“创建新工作树”弹窗中增加“依赖”开关。
- 弹窗每次打开时开关默认关闭。
- 关闭时不读取、不显示也不提交工作树引导依赖。
- 开启后才读取当前来源并显示既有来源选择器和候选列表。
- 关闭开关时中止未完成读取并清空读取结果与用户选择。

## 方案比较

### 采用：由连接层控制的按需依赖开关

`CreateWorktreeDialogConnected` 持有 `bootstrapEnabled` 局部状态并据此启动或停止预检；`CreateWorktreeDialog` 通过受控属性渲染开关和依赖区域。读取所有权继续留在已有连接层，展示组件只表达交互状态。

该方案不会产生默认请求，关闭状态也不会保留不可见选择，并与现有子工作区仓库依赖开关保持一致。

### 不采用：只折叠界面但继续自动预检

该方案改动较小，但没有消除无意义请求，也会保留不可见的来源、错误和候选状态。

### 不采用：让展示组件直接执行依赖读取

这会把仓库传输调用引入表单展示组件，与当前连接层负责异步读取的边界冲突，并产生重复状态所有权。

## 交互设计

- 在工作树路径字段后、依赖来源和候选列表前显示带“依赖”标签的现有 `Switch`。
- 开关在弹窗每次打开时为关闭状态；状态不持久化、不跨窗口同步。
- 关闭状态下不显示依赖来源、候选或预检错误，创建按钮不受依赖读取影响。
- 开启后立即按当前创建模式和分支上下文执行既有来源解析、主工作树回退和候选读取。
- 开启期间，依赖读取仍会暂时禁用创建按钮；读取失败后继续允许无依赖创建。
- 关闭时中止读取、清空来源、候选快照、错误和候选选择；重新开启会重新读取，所有候选恢复为“跳过”。
- 关闭期间切换基础分支或创建模式只更新来源上下文，不发起读取；开启期间切换继续触发既有重新读取逻辑。
- 提交路径同时检查开关状态；关闭时即使存在上一轮快照，也只提交 `worktreeBootstrap: { kind: 'skip' }`。

## 组件与状态

`CreateWorktreeDialogConnected` 新增：

```ts
const [bootstrapEnabled, setBootstrapEnabled] = useState(false)
```

其预检 effect 仅在 `open && bootstrapEnabled` 时执行。关闭弹窗时同时重置开关与全部来源状态；仅关闭开关时保留当前表单所选分支上下文，以便再次开启后读取正确来源。

`CreateWorktreeDialog` 新增受控属性：

```ts
bootstrapEnabled?: boolean
onBootstrapEnabledChange?: (enabled: boolean) => void
```

组件以 `false` 作为默认值，并以该值控制依赖忙碌状态、候选派生、依赖区域可见性和提交内容。

```text
dialog opens
  -> dependency switch off
  -> no preflight

dependency switch on
  -> resolve current source
  -> load preflight
  -> show source picker and candidates

dependency switch off
  -> abort in-flight request
  -> clear source, preflight, error, and choices
  -> submit skip
```

## 错误与生命周期

- 关闭依赖开关会通过 effect cleanup 中止当前 `AbortController`。
- 预检错误仅在开关开启时显示现有错误文案，并保持非阻塞创建语义。
- 弹窗关闭后开关恢复关闭；重新打开不会自动预检。
- 不新增服务端 API、缓存、realtime、持久化字段或包依赖。

## 测试

1. 展示组件默认渲染关闭的依赖开关，并隐藏传入的旧候选快照。
2. 开关开启时显示来源和候选；关闭状态提交不包含候选来源。
3. 打开真实创建工作树入口不会调用预检。
4. 开启开关后才调用预检并显示候选。
5. 关闭开关会中止读取、隐藏候选并使提交回到 `skip`。
6. 重新开启会重新读取，候选选择恢复为“跳过”。
7. 关闭期间切换分支不读取；开启期间切换重新读取当前来源。
8. 四种语言字典保持键和值完整。

## 非目标

- 不改变新建或扩展子工作区的仓库依赖开关。
- 不改变依赖候选的复制、软链接、来源回退或服务端校验。
- 不保存依赖开关状态。
- 不重新设计创建工作树弹窗的其他字段。

## 工程与架构结论

- **KISS / YAGNI**：复用现有开关、来源选择器和候选列表，只增加一个局部布尔状态。
- **DRY**：继续复用已有预检 effect 和来源解析逻辑，不增加第二套读取路径。
- **SOLID**：连接层拥有异步读取，展示组件拥有表单呈现，两者通过受控属性通信。
- 该状态属于 `docs/state-sync.md` 定义的 Local state，不进入 Zustand 或服务端。
- 现有 **Worktree bootstrap**、**Worktree bootstrap source** 和 **Worktree bootstrap candidate** 已覆盖本次语义，因此不修改 `CONTEXT.md`。
- 决策局部、可逆且没有长期架构取舍，不创建 ADR。
