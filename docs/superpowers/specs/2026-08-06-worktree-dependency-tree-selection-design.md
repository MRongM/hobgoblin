# 工作树依赖文件树选择设计

**日期**：2026-08-06
**状态**：已确认并实施

## 问题

普通工作树和子工作区成员工作树目前都从 Git 未跟踪项中生成根级依赖候选列表。该模型不能选择
`backend/.venv`、`frontend/node_modules` 等位于受跟踪父目录下的深层依赖，也把依赖浏览绑定到了
Git 排除规则。

依赖是工作树创建后的辅助物化步骤。现有流程仍可能因为候选过期、目标冲突或复制/软链接失败而返回失败，
使已经成功的主工作树创建表现为失败。

## 目标

- 用可展开、可勾选的多级文件树替换 Git 未跟踪候选列表。
- 依赖来源下拉框列出仓库当前已存在的工作树。
- 用户可在来源工作树中选择任意深度的文件或目录，并为每项选择复制或软链接。
- Git 跟踪状态只在物化时判断；被跟踪的选择静默跳过。
- 来源失效、目标已存在、路径不安全或物化失败时静默跳过对应选择。
- 所有依赖问题都不报错、不回滚，也不阻碍普通工作树或子工作区成员工作树的主创建流程。
- 本地仓库与 SSH 仓库保持相同语义。

## 非目标

- 不提供自由文本路径输入。
- 不递归预加载整个来源工作树。
- 不把依赖选择持久化为仓库配置或默认模板。
- 不同步已经物化的依赖，也不在修复流程中重建依赖。
- 不改变工作区根级“子工作区依赖”的辅助条目模型。
- 不允许覆盖或替换目标工作树中已经存在的路径。

## 方案比较

### 采用：复用文件树读取边界，新增只读依赖选择树

复用现有 `getRepositoryFileTree` 和 `/api/repo/file-tree`，按展开动作懒加载目录。新增轻量依赖树组件，
只负责来源浏览、勾选和复制/软链接模式，不承接文件编辑、拖放、搜索、终端或上下文菜单。

该方案同时支持本地和 SSH，避免扫描 `.venv`、`node_modules` 等大型目录，也保持组件单一职责。

### 不采用：复用完整 `ProjectFileTree`

现有项目文件树同时拥有编辑、拖放、剪贴板、搜索、上下文菜单和多选行为。把它嵌入创建弹窗会引入无关能力，
增加状态耦合，并可能让用户误以为可以在依赖选择过程中修改来源工作树。

### 不采用：保留 Git 候选列表并增加深层入口

该方案继续保留两套选择语义，不能满足“由 Git 排除列表改为用户多级自由选择”的替换要求。

## 交互设计

### 来源工作树

- 普通工作树和每个待创建的子工作区仓库成员继续使用显式“依赖”开关，且每次打开默认关闭。
- 开启后显示来源工作树下拉框；选项来自仓库当前权威快照中的现有工作树。
- 主工作树、普通关联工作树和当前可用的 detached 工作树都可作为来源；待创建目标永不出现在列表中。
- 有对应现有工作树时，普通创建默认使用当前分支上下文的工作树，子工作区默认使用所选创建基准的工作树；
  否则默认使用仓库主工作树。
- 不再根据某个来源是否存在 Git 未跟踪候选而自动回退。
- 切换来源会中止旧目录读取，清空展开状态和全部选择，再从新来源根目录加载。

### 依赖文件树

- 文件树初始只读取来源根目录；展开目录时才读取其直接子项。
- 隐藏文件与普通文件使用相同规则展示。
- 每个普通文件和目录都有独立复选框；符号链接可展示但不可选。
- 勾选目录表示把该目录作为一个依赖，不级联勾选所有后代。
- 选择一个目录时删除已选后代；已有祖先被选中时，其后代不可重复选择。
- 新勾选项默认使用软链接；勾选后显示紧凑的复制/软链接切换控件。
- 取消勾选即从提交选择中移除。
- 目录读取失败只在该树节点显示可重试状态，不禁用主创建按钮。
- 依赖开关关闭或弹窗关闭时，清空来源、目录缓存、展开状态和选择。

## 状态与组件边界

新增聚焦组件 `WorktreeDependencyTree`：

- 输入：`repoId`、`sourceWorktreePath`、禁用状态和受控选择。
- 输出：规范化后的仓库相对路径与 `copy | symlink` 模式。
- 内部状态：已加载目录、展开节点、节点级加载/错误状态。
- 外部表单状态：已选路径及模式，随来源和弹窗生命周期重置。

依赖树状态属于 `docs/state-sync.md` 定义的 Local state，不写入 Zustand、不持久化，也不通过 realtime 同步。

`CreateWorktreeDialog` 与 `BranchWorkspaceDialog` 共用该组件。来源列表继续由现有仓库快照派生，但来源模型扩展为
当前所有现有工作树，而不是仅主工作树和带分支的工作树。

## 数据契约与读取路径

- 继续使用 `WorktreeBootstrapDecision` 表达一次性的来源与选择。
- `WorktreeBootstrapSelection.path` 改为安全、规范化的多级仓库相对路径。
- 删除已无调用者的候选作用域、候选预检 HTTP 路由、客户端方法、本地 Git 候选扫描和 SSH 候选脚本。
- 服务端不再把选择与 Git 候选快照做过期比较。
- 传输边界对每个选择独立规范化；畸形选择被丢弃，不使整个创建请求失效。
- 空选择等价于 `kind: 'skip'`。
- 来源路径仍必须解析为同一仓库当前已知的现有工作树；来源失效时仅把依赖决策降级为跳过。

读取流程保持现有分层：

```text
依赖树展开
  -> repo-client 边界
  -> repo read path
  -> 本地/SSH 文件树 source
  -> 当前目录直接子项
```

不新增持久化、缓存服务、轮询或 realtime 消息。

## 创建与物化流程

主流程顺序固定为：

```text
校验并执行 Git 工作树创建
  -> Git 创建失败：返回原有失败
  -> Git 创建成功：逐项最佳努力物化依赖
  -> 返回主创建成功
```

每个选择独立执行：

1. 规范化相对路径并拒绝绝对路径、空路径、`..`、控制字符和任意 `.git` 段。
2. 确认来源仍属于同一仓库的现有工作树；否则跳过全部依赖。
3. 使用 Git 查询选择路径。文件被跟踪，或目录下存在任意被跟踪文件时，跳过该选择。
4. 使用 `lstat` 确认来源是普通文件或目录；缺失、符号链接及其他类型均跳过。
5. 确认来源和目标的父路径不会经符号链接逃逸工作树边界。
6. 目标相对路径已经存在时跳过，不申请替换确认。
7. 复制使用同目录临时路径并在成功后重命名；软链接继续指向来源绝对路径。
8. 任一检查、Git 查询、复制或软链接报错时，清理该项临时内容并继续下一项。

显式取消会停止剩余依赖处理，但不会把已经完成的 Git 工作树创建改为失败。返回摘要只描述成功复制或软链接的
路径；跳过项不产生错误 toast、子工作区 warning 或不完整成员状态。

## 子工作区计划与执行

- 子工作区计划不再读取仓库依赖候选或校验候选过期。
- 依赖来源和选择仍绑定到对应仓库成员，不跨仓库共享。
- 计划重建时若来源已失效，将该成员的依赖决策降级为跳过，而不是使计划失效。
- 目标冲突不再进入替换审批；物化阶段直接跳过。
- 成员工作树创建成功后立即视为完成；依赖跳过或失败不生成 `repository-dependency-failed` warning。
- 工作区根级辅助依赖继续使用现有预览、替换审批和维护语义。

## 错误处理

- 文件树根目录读取失败：显示节点内重试，允许无依赖创建。
- 子目录读取失败：保留其他已加载节点与选择，允许重试或直接创建。
- 来源工作树在选择后消失：跳过全部依赖，主创建继续。
- 路径在选择后变为 Git 跟踪：跳过该项。
- 来源在选择后消失或改变类型：跳过该项。
- 目标路径已存在：跳过该项，绝不覆盖。
- 单项物化失败：清理临时内容并继续。
- 主 Git 创建失败：保留现有错误语义，不执行依赖物化。

## 测试策略

### Web

- 来源下拉框列出当前所有现有工作树，不受 Git 未跟踪内容影响。
- 来源切换清空加载树、展开状态与选择，并中止旧请求。
- 文件树按层懒加载，展示隐藏项，且读取错误不禁用创建。
- 文件与目录均可勾选；符号链接不可选。
- 目录选择不级联，并消除祖先/后代重叠选择。
- 新选择默认软链接，可切换为复制。
- 普通工作树和子工作区提交相同的多级路径契约。
- 依赖关闭时不读取文件树，也不提交残留选择。

### Shared / Server

- 多级相对路径可规范化；绝对、越界、`.git` 和控制字符路径被逐项丢弃。
- 一个畸形选择不使其他选择或主创建请求失败。
- 子工作区计划不再依赖候选预检，失效来源降级为跳过。

### Local / SSH

- 未跟踪深层文件和目录可复制或软链接到相同相对路径。
- 被跟踪文件，以及包含任意被跟踪文件的目录被跳过。
- 缺失来源、符号链接来源、目标已存在、父级软链接和单项物化错误均被跳过。
- 一个失败项不影响其他有效项。
- 全部依赖被跳过时，工作树创建仍返回成功。
- 本地与 SSH 生成相同的成功摘要。

## 工程原则

- **KISS**：复用现有文件树读取 API，只新增聚焦的只读选择组件。
- **YAGNI**：不新增文本语法、搜索、持久化模板或依赖同步。
- **DRY**：普通工作树与子工作区共用组件、契约和本地/SSH物化语义。
- **SOLID**：UI 负责局部选择，read path 负责目录读取，write/source 层负责创建后的最佳努力物化。

该决策不新增难以逆转的存储格式或跨系统协议，不创建 ADR。

## 验收标准

- 用户可从任一现有来源工作树的文件树中勾选任意深度的普通文件或目录。
- `backend/.venv`、`frontend/node_modules` 等深层未跟踪目录可按选择复制或软链接。
- 被 Git 跟踪的选择、目标冲突和所有依赖物化错误均静默跳过。
- 普通工作树与子工作区成员的主创建结果不受依赖处理影响。
- 本地与 SSH 行为一致，完整测试、类型检查和架构检查通过。
