# 工作区仓库列表高度调整与文件区工具栏线条设计

日期：2026-07-23

## 目标

1. 多仓库工作区的“工作区仓库”列表允许用户通过底部拖动柄调整高度。
2. 移除文件区“文件”“状态”“变更”三个面板中，内容工具栏下方的边线。

## 范围与约束

- 仓库列表默认高度保持为 `160px`，与当前 `max-h-40` 的视觉高度一致。
- 桌面高度按多仓库工作区根目录保存为可恢复状态，经 Zustand 的 restorable slice 写入 Session；应用重启后恢复各工作区上次高度。
- 高度调整仅在桌面界面启用。紧凑界面继续使用固定高度，避免与单表面导航和触摸滚动竞争。
- 拖动高度必须限制在可用导航区域内，并为下方导航内容保留最小空间。
- 不改变项目、仓库、分支工作区或文件区的领域模型。
- 不新增依赖，不修改共享 `Toolbar` 的全局默认样式。

## 交互设计

“工作区仓库”列表底部增加一个全宽、低视觉噪声的拖动柄。默认状态不绘制装饰线；鼠标悬停、拖动或键盘聚焦时显示现有品牌色反馈。拖动柄使用行调整光标，并提供可访问的分隔符语义。

列表内部继续使用纵向滚动。向下拖动增加可见仓库数量，向上拖动减少高度；调整值在最小高度与当前导航容器允许的最大高度之间截断。

紧凑界面不显示拖动柄，也不启用高度调整。

## 实现边界

### 工作区仓库列表

- `WorkspaceRepositoryListPane` 作为受控组件处理调整交互；`WorkspaceRepositoryRail` 按工作区根目录从 restorable store 读取高度并写回。
- 将高度计算和边界截断提取为小型纯函数，便于测试。
- 拖动开始时记录起始指针位置和起始高度；移动时按纵向偏移更新高度；结束或取消时解除监听。
- 列表容器由固定最大高度改为受控高度和纵向滚动。
- 旧 Session 或缺少当前工作区记录时使用 `160px`；恢复到更小窗口时按当前导航区可用高度截断。
- 复用现有分隔柄的视觉语言，但不重构整个工作区导航为嵌套面板。

### 文件区工具栏

- 文件面板：仅移除 `ProjectFileTree` 内容操作栏的底边框类。
- 状态面板：通过 `ProjectStatusToolbar` 的局部 class 覆盖移除底边框。
- 变更面板：仅移除 `ProjectChangesActionBar` 的底边框类。
- 文件区 Tab 栏及其他面板工具栏保持不变。

## 测试策略

- 先新增失败测试，验证桌面仓库列表使用默认受控高度并渲染拖动柄。
- 验证拖动和键盘调整会按工作区根目录写入可恢复状态，且最小值和最大值会被截断。
- 验证 Session 往返、应用启动恢复、不同工作区高度隔离及关闭工作区后的记录清理。
- 验证紧凑界面不渲染拖动柄。
- 分别验证文件、状态、变更工具栏不再包含底边框样式，同时仍保留工具栏背景和高度。
- 最后运行定向测试、`bun run typecheck`、`bun run test` 和 `bun run check:architecture`。

## 非目标

- 不跨 renderer 实时同步仓库列表高度；它只在下次启动时恢复。
- 不持久化或恢复紧凑界面的固定列表高度。
- 不允许调整项目列表、普通分支列表或文件区 Tab 栏高度。
- 不统一移除应用内所有工具栏边框。
- 不重构 `SplitPane` 或工作区导航层级。
