# 子工作区创建与删除弹窗进度设计

**日期**：2026-07-27  
**状态**：已实施

## 背景

子工作区弹窗已经通过计划步骤明确列出创建或删除将执行的工作。确认后，服务端会顺序执行这些步骤，并在每个仓库成员或附属条目完成、移除或失败时持久化状态并发布工作区失效通知。

当前发起操作的 Renderer 会用 `sourceToken` 抑制自己的失效通知，弹窗也只持有打开时的工作区快照。因此确认执行后，静态计划仍留在弹窗内，但没有步骤状态或完成数量，长时间操作看起来像停止响应。

## 目标

1. 创建和删除子工作区时，在原确认弹窗内实时显示每个计划步骤的“等待 / 进行中 / 完成 / 失败”状态。
2. 显示“已完成 X/Y”，其中 X 是已经完成的计划步骤数，Y 是本次计划的全部步骤数。
3. 复用现有服务端持久化状态和 WebSocket 失效加定向重读路径，不伪造耗时百分比。
4. 保持现有成功关闭、失败留在弹窗、重试和取消语义。

## 非目标

- 不显示耗时百分比、剩余时间或速度预测。
- 不为单个 Git、SSH、复制命令增加字节级或命令级进度协议。
- 不改变扩展、缩减、修复或依赖维护弹窗。
- 不改变服务端计划、审批、安全边界、顺序执行、失败恢复或取消协议。
- 不新增 Electron 专用路径。

## 交互设计

计划预览阶段保持现有静态步骤列表。用户确认创建或删除后，同一列表切换为进度表示：

- 列表上方显示“正在创建子工作区…”或“正在删除子工作区…”，以及“已完成 X/Y”。
- 每个步骤右侧显示状态文字和图标：等待使用中性圆点，进行中使用旋转图标，完成使用成功色勾选，失败使用危险色错误图标。
- 步骤顺序就是实际执行顺序；只有第一个尚未完成且未失败的步骤显示为“进行中”。
- 清理本地分支和上游分支的既有分组布局保留，每个分支步骤独立显示状态。
- 确认按钮在执行中保持禁用并显示旋转图标；取消按钮继续调用现有中止接口并关闭弹窗。
- 成功后按现有行为立即关闭弹窗，不人为停留展示 `Y/Y`。
- 失败后弹窗保留，已完成步骤保持完成，失败步骤显示失败，未执行步骤保持等待，并继续显示现有错误和重试按钮。

所有样式复用现有主题 token、Lucide 图标和排版，不增加新的颜色、字体或动画体系。步骤序列本身作为主要信息结构。

## 状态投影

新增纯 Renderer 投影函数，以 `BranchWorkspacePlan.steps`、实时 `BranchWorkspaceSnapshot`、执行中标记和最终失败标记为输入，输出步骤状态和完成计数。

已完成和失败的判断来自现有权威字段：

- 创建目录：子工作区根目录已存在且是目录。
- 创建工作树：对应成员 `progress === 'complete'`；`failed` 表示失败。
- 复制或链接附属条目：创建中的快照不再包含该待处理条目时视为完成；`failed` 表示失败。
- 删除工作树：对应成员 `progress === 'removed'`；`failed` 表示失败。
- 删除本地或上游分支：对应 cleanup progress 为 `complete` 或 `failed`。
- 删除附属条目：对应条目 `progress === 'removed'` 或 `failed`。
- 未纳管内容和最终目录删除没有独立持久化进度；它们保持为当前步骤，直到请求成功并关闭弹窗，或失败结果将第一个未完成步骤标记为失败。

服务端严格顺序执行，因此如果后续步骤已完成或失败，位于它之前但没有独立可观察字段的步骤可安全投影为完成。完成计数只统计 `complete`，不把进行中或失败计入 X。

## 数据流

1. `BranchWorkspaceDialog` 继续提交计划与审批。
2. `useBranchWorkspaceActions.confirm` 执行生命周期请求时不再创建 `sourceToken`，使当前 Renderer 接收该请求产生的工作区失效通知；其他 mutation 的自回声抑制保持不变。
3. TanStack Query 根据既有工作区失效事件定向重读当前 root。
4. `WorkspaceRepositoryRail` 根据 `plan.branchWorkspaceId` 从最新查询结果中解析实时进度快照，并与打开弹窗时的稳定 `workspace` 分开传入。
5. 弹窗用纯投影函数生成步骤状态和完成计数，不保存平行的进度状态。

这是 invalidation + refetch，而不是连续流。每个持久化步骤最多触发一次现有快照重读，符合项目 realtime 约定；轮询和新流式协议都没有必要。

## 分层与状态所有权

- 服务端清单仍是运行时一致事实来源，不新增协议或持久字段。
- TanStack Query 继续拥有 Renderer 的运行时一致投影。
- 弹窗是否正在执行属于短期本地交互状态，继续由现有 Hook 的 `pending/result` 表达。
- 计划到视觉状态的映射放在 `repo-workspace` 功能目录的纯模块中，组件只负责渲染。
- `WorkspaceRepositoryRail` 只负责把查询中的目标快照传给弹窗，不复制业务规则。

## 错误与边界

- 执行请求在第一个服务端快照到达前，第一个计划步骤显示进行中，其余步骤等待。
- 快照短暂读取失败时沿用查询的结构共享策略，保留上次成功快照，不倒退已显示的状态。
- 最终失败但没有可观察的细分失败字段时，将第一个未完成步骤显示为失败；现有错误文本仍提供具体原因。
- 删除最后一步会移除清单记录；成功响应会立即关闭弹窗，不把“查询不到条目”解释为失败。
- 空计划继续显示现有“所有预期内容均已满足”，不显示 `0/0` 进度。

## 测试策略

### 纯投影测试

- 无实时快照时，第一个步骤进行中，其余等待，完成数为 0。
- 创建目录、多个仓库成员和附属条目按权威状态推进。
- 删除工作树、本地分支、上游分支和附属条目按权威状态推进。
- 后续步骤已落盘时，前面的不可观察步骤按顺序推断为完成。
- 最终失败将第一个未完成步骤标记失败，完成数不增加。

### Hook 与 Rail 测试

- 生命周期 execute 请求不携带 `sourceToken`，从而不抑制当前 Renderer 的工作区进度失效。
- 成功创建快照仍直接写入缓存；没有快照的结果仍执行最终失效。
- Rail 将与计划 ID 匹配的最新查询快照作为独立进度快照传给弹窗。

### 弹窗测试

- 创建执行中显示创建文案、`X/Y`、步骤状态和禁用的旋转确认按钮。
- 删除执行中显示删除文案并保留 destructive 按钮语义。
- 计划预览和其他模式不显示进度状态。
- 失败后保留完成、失败和等待状态，并保留重试。
- 四种语言字典键完整。

### 全量验证

```text
bun run typecheck
bun run test
bun run check:architecture
```

## 方案取舍

选择复用持久化步骤状态和现有失效重读，而不是轮询或新增进度协议：

- 进度来自服务端事实，不伪造百分比；
- 变化集中在 Renderer 写路径、查询投影和弹窗；
- 不引入新的跨进程状态机；
- 其他 mutation 的自失效抑制不受影响；
- 符合 KISS、DRY 和 YAGNI。

不创建 ADR：该选择是现有子工作区生命周期 UI 的局部、可逆扩展，没有新的长期架构边界。
