# Android tmux 扫描目录手动导入项目设计

**日期**：2026-07-29  
**状态**：已确认，自主 inline 实施

## 目标

允许用户从 Android 主页 tmux Tab 的扫描结果中，手动把某个目录导入设备本地项目列表。导入复用现有项目设置页：预填当前 SSH 主机和扫描目录，用户可确认或修改名称与路径，保存前仍执行已有远端项目检查，以识别 Git 仓库或普通工作区并解析规范项目路径。

## 方案选择

采用“导航到预填的现有项目设置页”。

- 不直接把扫描目录保存为项目，因为 tmux 元数据只证明目录曾是终端初始路径，不能判断它是 Git 仓库、linked worktree 还是普通工作区。
- 不在 tmux 页新增独立导入弹窗，因为这会复制主机选择、目录检查、类型识别、错误反馈和保存逻辑。
- 复用 `RepositorySetupScreen`，保持项目持久化与远端检查只有一个写入入口。

## 交互

每个 `HostTmuxPathGroup` 的目录标题行增加“导入项目”动作：

1. 点击动作后进入项目设置页。
2. 项目设置页锁定式预选当前扫描主机，但仍允许用户主动切换主机；远端路径预填为该组规范化的 `initialPath`，别名保持为空。
3. 用户点击“保存项目”后执行现有 `inspectProject` 流程：Git linked worktree 会解析到 primary worktree，普通目录会保存为普通工作区。
4. 保存成功后，从 tmux 发起的流程返回同一主机的 tmux Tab；普通“添加项目”入口继续停留在项目设置页，现有行为不变。
5. 若当前主机已有规范路径与扫描路径完全相同的项目，目录标题行显示“已导入”且禁用重复入口。

“已导入”只依据设备本地保存项目的 `hostProfileId + normalized remotePath`。tmux 扫描协议无法从 project-scoped server hash 反推出 Git primary worktree，因此不在 tmux 列表中猜测 linked worktree 与已保存项目的关系；保存时的远端检查仍负责规范化路径。

## 架构与数据流

### 导航

把 `AppRoute.AddRepository` 从无参数对象改为带默认参数的数据类：

- `initialHostId: String?`
- `initialRemotePath: String?`
- `tmuxReturn: TmuxReturn?`

普通项目入口创建默认路由；tmux 目录入口携带当前主机、目录和返回上下文。导航状态只描述当前交互，不新增持久化状态。

### UI

`TmuxScreen` 接收当前设备本地项目列表和 `onImportDirectory(path)` 回调。目录头仅负责展示导入可用性并发送路径，不写项目、不执行 SSH。

`RepositorySetupScreen` 新增可选初始主机与初始路径参数。Compose 本地表单状态以这些参数初始化；后续用户编辑仍沿用现有行为。

### 写入

唯一持久化入口仍是 `RemoteRepositoryStore.saveRepository`。tmux 页面不直接依赖 Store，不新增协议、数据库或后台同步。

数据流为：

`tmux 目录动作 -> 带参数导航 -> 项目设置表单 -> 远端检查 -> RemoteRepositoryStore -> 刷新项目投影 -> 返回 tmux`。

## 错误与边界

- 目录导入前主机被删除：项目设置页无法解析预选主机，回退到现有可认证主机选择；返回仍指向 tmux，tmux 页面会按现有规则回到主机选择态。
- 目录不可读、SSH 失败或检查失败：复用项目设置页现有错误反馈，不写入项目，也不离开页面。
- 用户切换主机：允许继续，但导入结果属于新选择的主机；预填路径仍可编辑。
- 保存成功前 Back：不写入任何项目，返回原 tmux 主机上下文。
- 已保存项目的精确路径匹配使用 tmux 协议已有路径规范化函数，避免尾斜杠和冗余段造成重复入口。

## 测试策略

- 导航测试：普通添加项目使用空初值；tmux 导入携带主机、路径和返回上下文。
- 项目设置状态测试：有效预选主机优先于默认主机；无效预选回退到现有默认；初始路径进入表单状态。
- tmux 展示测试：未导入目录提供导入动作；同主机同规范路径显示已导入；其他主机相同路径不算已导入。
- App 合同测试：tmux 导入路由预填设置页；保存成功与 Back 都返回同一 tmux 主机；普通添加项目行为不变。
- 资源测试：英文、简体中文、日文、韩文新增字符串保持完整。
- 回归验证：Android unit test 与 `assembleDebug`，根项目 `typecheck`、`test` 和 `check:architecture`。

## 非目标

- 不自动导入扫描到的所有目录。
- 不从 tmux server 名称推断项目根目录。
- 不修改远端 tmux 扫描、恢复、关闭或删除协议。
- 不持久化“扫描目录已导入”的独立映射。
- 不新增依赖或新的项目存储格式。

## 原则检查

- **KISS**：一个目录动作跳转到现有表单，写入流程保持单一。
- **YAGNI**：不增加自动导入、批量导入或额外映射。
- **DRY**：远端检查、项目类型识别和持久化完全复用。
- **SOLID**：tmux UI 只发送意图，导航携带上下文，项目设置页负责表单与检查，Store 负责持久化。
