# 子工作区批量更换上游设计

## 目标

让用户从一个子工作区父项中，为多个成员工作树的目标本地分支分别选择并批量更新 Git upstream。不同成员仓库可以选择不同远端和远程分支。

## 领域边界

- `Branch upstream` 仍然是一个本地分支的 Git 配置，和工作树、创建来源及子工作区创建基准无关。
- `Branch workspace batch upstream change` 是一次父级子工作区动作；它为每个选中的成员仓库映射一个已发现的远程跟踪分支。
- 它不创建、删除、拉取、推送或合并分支，不修改成员工作树内容，也不把一个仓库的远端假设用于另一个仓库。

## 交互

在就绪子工作区父项的“更多”菜单中新增“批量更换上游”。动作打开既有的内联批量动作面板：

- 有远程候选的成员默认勾选，但每个选中的成员必须显式选择一个远程分支；不隐式沿用当前上游。
- 每一行显示成员仓库、目标本地分支、当前上游（包括已失联状态）和该仓库自己的可搜索远程分支选择器。
- 没有远程候选或成员目标无法验证的行不可选择，并展示原因。
- 可使用全选/取消全选；未选择成员不会进入本次执行。
- 开始后选择和复选框锁定，行内展示当前执行步骤、已完成、失败或未选择状态；`upstream` 步骤只表示进行中或失败位置，成功行沿用既有的“已完成”阶段。

## 计划、执行与失败语义

计划读取每个成员目标分支的当前上游与该仓库已发现的远程跟踪分支。计划指纹绑定成员身份、目标分支、目标提交、当前上游（含失联状态）和候选远程引用；不绑定未影响上游配置的工作树脏状态。

服务端只接受非空、无重复的成员/远程引用映射，并按子工作区清单顺序重排。执行前重新建立并校验计划，确认目标成员和选中的候选没有变化。之后逐个调用既有的仓库后端上游设置能力。

批次不是跨仓库事务：失败时停止，不回滚已成功的设置。重试只能使用第一次执行锁定的成员/远程引用映射，跳过已完成成员。取消会在当前成员调用的安全边界后停止后续成员。成功或尝试后的受影响仓库均通过既有失效机制刷新。

## 架构与状态所有权

- 共享层扩展子工作区批量动作的判别类型、成员计划、执行映射、步骤和严格输入规范化。
- 服务端计划层复用 `readMemberFacts(..., true)` 和既有远程分支读取，不增加路由、轮询或持久化。
- 服务端写路径复用 `setRepositoryBranchUpstream`，拥有执行锁、重试绑定、顺序、取消和失效发布。
- Renderer 只拥有当前面板的复选、搜索词和远程引用选择；服务端计划拥有可执行事实。
- 本地和 SSH 仓库继续由 `RepoBackend` 隐藏差异。

## 测试与验收

- 共享协议拒绝空映射、重复成员、非法仓库名和无效远程引用。
- 计划按清单顺序投影成员上游与远程候选，候选不足时保持可见但不可执行，并在上游或候选变更时失效。
- 写路径按清单顺序设置各自上游，失败后停止，重试固定映射并跳过已完成成员。
- Hook 与组件测试验证计划请求、成员选择、显式远程选择、行状态与菜单入口。
- 四种语言字典包含动作、说明、字段、状态与步骤文案。
- 运行定向测试、`bun run typecheck`、`bun run test` 和 `bun run check:architecture`。

## 不采用的方案

1. 统一指定同名远程分支：不同成员仓库的远端和分支命名不一定一致，无法表达实际目标。
2. 逐个打开现有单分支弹窗：保留了重复操作，不能提供批量进度、失败和重试语义。
3. 把上游写入子工作区清单：上游是仓库本地分支的 Git 状态，不是子工作区持久化配置。

## 架构压力检查

- 每个仓库仍是独立 Git 操作边界；输入只用成员名匹配服务端计划中的同仓库目标分支。
- Renderer 不传递路径或自行信任远程引用；服务端以计划候选重新验证。
- 失败不会造成隐藏回滚或覆盖其他成员的设置；已经完成的设置明确保留并可安全重试。
- 不引入 Electron 依赖、跨层导入、全局状态或新包。
