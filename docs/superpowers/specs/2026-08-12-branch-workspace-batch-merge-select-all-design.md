# 子工作区批量合并全选设计

**日期**：2026-08-12  
**范围**：子工作区批量合入、批量合出成员选择

## 背景

批量合入与批量合出弹窗已经允许逐个勾选成员工作树，并默认选中全部可用成员，但缺少一个可见的全选入口。用户需要逐项取消后再恢复全部选择时，只能逐个操作。

批量提交、批量丢弃、批量拉取和批量推送没有成员子集选择模型，本次不改变这些动作的既有语义或协议。

## 设计

- 在批量合入与批量合出弹窗的成员计数区域增加三态“选择全部可用成员”复选框。
- 可选成员沿用各弹窗现有资格规则：
  - 批量合入：成员就绪且至少存在一个来源分支。
  - 批量合出：成员就绪且至少存在一个就绪目标分支。
- 全部可选成员已选中时显示选中；部分已选中时显示半选；均未选中时显示未选中。
- 点击未完全选中的全选框时选择全部可选成员；点击已完全选中的全选框时取消全部可选成员。
- 不可用成员不参与总数、全选状态或批量切换，继续保持禁用和未选中。
- 批次执行或锁定后，全选框与成员复选框一起禁用，避免改变已绑定的执行输入。
- 弹窗打开时仍默认选择全部可用成员，不改变现有默认行为。

## 实现边界

- 变更限定在 Renderer 的批量合并弹窗、国际化字典及组件测试。
- 复用同一文件内的小型全选控件和纯选择状态计算，避免批量合入、批量合出重复三态逻辑。
- 不修改服务端计划、执行协议、批次顺序、错误隔离、重试或进度模型。
- 不新增依赖，不修改 `CONTEXT.md`；现有“Branch workspace batch merge-in/out”术语足以描述该能力。

## 验证

- 批量合入：验证默认全选、部分选择半选、全选恢复、再次点击全部取消及不可用成员不受影响。
- 批量合出：验证相同三态与切换行为。
- 验证批次锁定时全选不可操作。
- 运行目标组件测试、`bun run typecheck`、`bun run test` 和 `bun run check:architecture`。

## 原则

- **KISS / YAGNI**：只补齐已有成员选择界面的全选入口，不给无成员选择模型的批量动作扩展协议。
- **DRY**：合入与合出复用三态计算和全选控件。
- **SOLID**：全选控件只负责呈现和发出选择意图，成员资格仍由各批量动作定义。
