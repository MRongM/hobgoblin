# 新增子工作区并行同步全部仓库设计

## 目标

在“新增子工作区”选择界面的标题区右侧和工作区根节点的“更多”菜单中提供“同步全部仓库”动作。用户可在创建子工作区前或日常工作区导航中，一次刷新当前多仓库工作区中所有已配置仓库的远端引用与本地仓库投影。

## 范围

- 仅在 `BranchWorkspaceDialog` 的 `create` 模式且尚未生成预览计划时显示按钮。
- 仅在已配置且至少包含一个仓库的工作区根节点“更多”菜单中显示菜单项；普通 Git 项目和未识别的普通目录不显示。
- 同步目标为当前工作区已配置的全部仓库，不受成员工作树勾选状态影响。
- 不在扩展、缩减、修复、删除或计划确认/执行界面显示按钮。
- 不新增服务端 batch API，不修改数据库、配置文件或可恢复状态。

## 方案比较

### 采用：Renderer 并行编排现有单仓库同步动作

为现有 `syncAndRefresh` 返回单仓库 fetch 结果，再由一个窄职责的 branch-workspace 批量协调器通过 `Promise.allSettled` 并行调用。该方案复用已有本地、SSH、WSL Git 后端、操作队列、网络代理、超时、失效广播和仓库快照刷新逻辑。

优点是改动小、错误结果可准确汇总，并保持既有仓库操作状态可见；代价是 Renderer 负责一次轻量的批量协调。

### 未采用：新增服务端 batch-fetch API

服务端可统一编排，但需要新增共享协议、路由、写路径、取消和进度模型。当前需求不需要跨窗口共享批量进度，成本高于收益。

### 未采用：组件直接并发调用 `/api/repo/fetch`

实现最短，但会绕过 repo store 的单仓库操作队列和刷新管线，容易造成操作状态与仓库投影不一致。

## 组件与数据流

1. `BranchWorkspaceDialog` 渲染标题区按钮并维护按钮的短生命周期 pending 状态。
2. 工作区级适配器在动作真正执行时从 repo store 读取目标工作区的最新仓库成员、名称和 instance token。
3. `WorkspaceRepositoryRail` 把该批量动作传给 Dialog；`SidebarProjectList` 将同一动作接入工作区根节点菜单。
4. 批量协调器同时调用每个目标的 `syncAndRefresh(id, { token })`。
5. `syncAndRefresh` 继续执行“能力重探测 → best-effort fetch → 无条件刷新 snapshot/status”的既有管线，并把 fetch 结果返回给调用方。
6. 批量协调器等待所有目标 settled，返回成功数与逐仓库失败信息。
7. Dialog 和工作区菜单复用同一 success/warning toast 反馈。Dialog 中已选仓库的远程分支列表随后独立刷新；读取失败保留现有本地分支选择能力。

## 并发与错误语义

- 所有仓库任务在同一轮事件循环中启动，不串行等待前一个仓库。
- 使用 `Promise.allSettled`；任意仓库返回失败或抛出异常都不会阻止其他仓库执行。
- `syncAndRefresh` 因操作繁忙或状态失效而没有结果时，按 `error.network-op-in-progress` 记为该仓库失败。
- 失败通过 warning toast 汇总，不写入 Dialog 的计划错误状态，也不禁用分支名、成员选择或预览按钮。
- 按钮在当前批次 pending 时禁用并显示旋转图标，防止重复提交；Dialog 关闭不新增专属取消机制，继续依赖现有仓库操作取消能力。

## 状态所有权

- 批量按钮 pending：Dialog 本地状态；菜单动作 pending：共享菜单组件本地状态。
- 单仓库操作、fetch 结果、snapshot/status：现有 repo store/runtime-coherent 投影。
- toast：一次性交互反馈。
- 不新增持久化或跨窗口批量状态。

## 交互与文案

- 按钮使用现有 `outline` 小尺寸样式和 `RefreshCw` 图标，放在标题/描述右侧并为原有关闭按钮预留空间。
- 工作区根节点菜单项使用同一文案和 `RefreshCw` 图标，由菜单现有异步动作机制显示 busy 状态。
- 中文使用“同步全部仓库”，与现有 fetch 文案“同步”保持一致。
- 成功提示说明全部仓库已同步；部分或全部失败提示完成数，并在描述中列出 `仓库名: 错误`。
- 英文、日文、韩文补齐同一组 key。

## 测试与验收

- 单元测试证明所有仓库并行启动。
- 单元测试证明返回失败和抛出异常均被隔离、其他仓库仍完成。
- store 测试证明 `syncAndRefresh` 返回成功、失败和无远端结果，同时仍刷新本地投影。
- Dialog 测试覆盖显示范围、pending 图标、成功 toast、失败 warning 及表单不被禁用。
- Rail 测试覆盖批量回调使用全部已配置仓库及各自最新 instance token。
- 工作区菜单测试覆盖显示范围、全部成员调用、部分失败汇总和动作独立完成。
- i18n 字典测试覆盖四种语言。
- 运行目标测试、`bun run typecheck`、`bun run check:architecture` 和 `bun run test`。

## 自检

- 无 TBD/TODO 或未决交互。
- “全部仓库”明确为工作区全部已配置仓库，而非当前勾选子集。
- “报错不要阻塞”同时覆盖成员间隔离与创建表单不锁定。
- 工作区菜单入口不复用旧的串行 pull-all 服务端流程；它与新增子工作区按钮保持相同的并行 fetch 语义。
- 方案不引入数据库、服务端协议或持久化状态。
