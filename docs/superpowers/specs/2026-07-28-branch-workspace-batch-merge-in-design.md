# 子工作区批量合入设计

**日期**：2026-07-28  
**状态**：已实施

## 背景

子工作区当前已有一条批量流水线：把所选成员工作树的目标分支合并到每个仓库显式选择的本地目标分支。该行为属于批量合出，但协议和界面仍使用含糊的“批量合并”名称。

本次增加相反方向：用户为所选成员显式选择一个本地来源分支，并把该来源分支合入成员工作树已经检出的目标分支。两个方向在 UI 中使用独立入口，服务端计划与执行身份也显式区分方向。

## 目标

1. 子工作区菜单提供独立的“批量合入”和“批量合出”入口。
2. 批量合入允许选择非空成员子集，并为每个成员显式选择一个现有本地来源分支。
3. 不从成员基准分支、创建来源、默认分支或上游推断来源分支，也不持久化本次选择。
4. 仅合入执行 `merge`；远端模式按目标成员分支执行 `pull → merge → push`。
5. 继续使用清单顺序、逐成员串行、首次失败停止、不回滚已完成写入、固定输入重试的批次语义。
6. 保留现有批量合出能力，并把共享协议、界面文案和领域术语改为明确的方向名称。

## 非目标

- 不支持远端跟踪引用作为来源；来源必须是同一仓库的现有本地分支。
- 不创建来源分支或来源工作树，不拉取或推送来源分支。
- 不把来源工作树的未提交内容视为来源分支内容；Git 合并只读取所选本地分支引用。
- 不并行执行成员，不提供跨仓库事务、自动回滚、自动冲突解决或命令级百分比。
- 不改变批量提交、批量拉取、批量推送和仓库级单分支合并。

## 领域模型

`Branch workspace batch merge-in` 把每个所选仓库成员的显式本地来源分支合入该成员的目标分支。目标成员工作树既是 Git 写入位置，也是冲突现场。

`Branch workspace batch merge-out` 把每个所选成员的目标分支合到显式本地目标分支。它可能复用现有目标工作树，也可能使用受控的应用临时工作树。

两个执行输入保持方向专属，避免一个模糊的 `branch` 字段：

```ts
interface BranchWorkspaceBatchMergeInSourceInput {
  repositoryName: string
  sourceBranch: string
}

interface BranchWorkspaceBatchMergeOutTargetInput {
  repositoryName: string
  destinationBranch: string
}
```

服务端使用 `batch-merge-in` 与 `batch-merge-out` 两个判别值。方向、模式、按计划排序后的成员和每个成员的分支映射共同构成首次执行身份。

## 交互设计

子工作区项目菜单在批量推送之后依次显示“批量合入”和“批量合出”。两个入口分别打开前台弹窗，不在弹窗内提供方向切换。

批量合入弹窗沿用现有批量合出弹窗的表格、宽度、成员选择、锁定、进度和错误呈现：

- 每行显示成员复选框、仓库名、成员目标分支、方向箭头、来源分支选择器和状态；
- 方向表达为 `来源分支 → 成员目标分支`；
- 目标成员工作树干净且存在至少一个其他本地分支的成员默认选中，但来源分支不默认选择；
- 所有选中成员都选择可用来源后，“仅合入”才可执行；
- “拉取、合入并推送”还要求每个所选成员目标分支都有可用上游；
- 执行开始后锁定成员、来源分支和模式。

来源选择器列出除成员目标分支外的所有本地分支。来源是否在工作树中检出、其工作树是否有未提交内容，都不改变本地分支引用本身的可合入性；界面不暗示未提交内容会被包含。

进度步骤与真实管线一致：

- 仅合入：`合入`；
- 远端模式：`拉取 → 合入 → 推送`。

现有弹窗和菜单文案改称“批量合出”，但保留其目标选择、准备和临时工作树清理语义。

## 计划与校验

批量合入计划为每个成员提供：

- 目标仓库、目标分支、目标工作树、目标提交和干净状态；
- 除目标分支外的本地来源分支列表及各自提交；
- 目标分支是否具有可用上游；
- 绑定目标提交、目标工作树状态和来源分支身份集合的成员指纹。

首次执行前重新构建计划并校验所有被选成员。仅合入模式要求目标提交、目标状态和所选来源提交均未变化。远端模式允许目标提交因本次 `pull` 变化，但在 `merge` 前再次确认目标工作树仍干净、路径未漂移且所选来源提交未变化。

未选择成员的提交或工作树变化不阻断批次；成员身份或清单顺序变化仍使计划过期。来源分支被删除、改名或提交变化时，在该成员 Git 写入前停止。

## 执行、冲突与重试

所选成员按清单顺序串行执行。单成员成功后记入 `completed`；远端模式分别记录已拉取、已合入和已推送步骤。失败后相同方向、模式和来源映射可重试并跳过已完成步骤；任何输入变化在新写入前被拒绝。

合入冲突保留在成员目标工作树中，供用户直接解决。批次停止且不自动清理或回滚冲突。用户完成解决或中止合并后，应重新打开操作以取得新计划；同一活动计划不会把人工处理结果猜测为成功。

## 状态与分层

- 共享层定义方向专属计划、输入和严格规范化。
- 服务端计划层投影来源候选与目标上游事实。
- 服务端写路径拥有重校验、顺序执行、步骤恢复、取消和失效发布。
- Renderer 只持有弹窗内选择，并把服务端活动快照投影为进度。
- Git 与 SSH 差异继续由现有 repository backend 隐藏。

不增加全局 store、持久字段、轮询、Electron 专用协议、新依赖或通用 service。

## 测试策略

- 共享协议：两个方向分别接受合法非空映射，并拒绝空列表、重复仓库、非法名称和方向错误字段。
- 计划：合入候选排除目标分支；脏目标成员禁用；来源工作树状态不影响来源分支；目标上游状态正确投影。
- 写路径：按清单顺序合入不同来源；远端模式只拉推目标；校验来源提交；绑定方向、模式和映射；失败停止且保留目标冲突现场。
- Renderer：两个独立入口；批量合入必须逐成员选择来源；方向呈现、按钮可用性、锁定、重试和步骤进度正确。
- 文档与多语言：四种语言区分 merge-in/merge-out，领域词汇不再使用含糊的 batch merge。
- 全量验证：`bun run typecheck`、`bun run test`、`bun run check:architecture`、`git diff --check`。

## 架构压力检查结论

- **仓库隔离**：每个成员仍是独立 Git 写入边界，来源只能来自同一仓库。
- **目标所有权**：批量合入始终写入成员工作树，不需要也不允许临时目标工作树。
- **状态所有权**：选择是组件本地状态；计划、活动与重试身份由服务端拥有。
- **远端语义**：只拉取和推送作为目标的成员分支，来源分支上游与管线无关。
- **冲突可见性**：冲突保留在用户可见的成员工作树，不清理、不迁移、不猜测完成。
- **分层**：边界只解析方向专属输入，策略不泄漏到 Renderer，未引入 Electron 分支。

不创建 ADR：该设计是在现有子工作区 Git 动作边界内增加对称方向，没有引入难以逆转的跨功能平台决策。
