# 新增与删除子工作区弹窗 UI 优化设计

**日期**：2026-08-26
**状态**：已实施

## 目标

把新增子工作区和删除子工作区的一步式弹窗优化为面向开发者的“操作控制台”：在不扩大页面占用、不改变计划与执行协议的前提下，让用户能快速辨认当前操作、配置范围、权威执行清单、风险确认和最终动作。

目标用户是同时管理多个仓库和成员工作树的开发者。弹窗的唯一工作是让用户在一次提交前清楚回答三个问题：

1. 正在新增还是删除哪个子工作区；
2. 当前配置会产生哪些操作；
3. 点击主按钮后将执行什么以及有哪些不可逆影响。

## 范围

本次只优化 `BranchWorkspaceDialog` 的两个模式：

- `create`：新增子工作区；
- `remove`：删除整个子工作区。

以下行为保持不变：

- 增加或移除成员工作树、修复子工作区；
- 子工作区依赖维护弹窗；
- 请求构造、自动规划、防抖、取消、计划令牌、审批和执行恢复；
- 仓库依赖选择、复制/软链接方式和执行清单内容；
- 四语言现有领域词汇。

本设计继续使用“子工作区”“成员工作树”“操作计划”与“强制删除”。不新增领域术语，因此不修改 `CONTEXT.md`；改动局部且可逆，不创建 ADR。

## 设计方向

### 采用：操作控制台

新增与删除使用同一骨架，但有清晰的操作语气：

- 新增使用成功语义色，表达“将生成新结构”；
- 删除使用危险语义色，表达“将移除现有结构”；
- 中央主体保持中性，颜色只用于操作标识、关键边界和不可逆动作；
- `01 配置 → 02 执行清单 → 最终操作` 形成连续的操作轨道。

序号在这里表示真实的信息顺序：先配置，再核对服务端计划，最后提交；不是装饰编号。

### 未采用：仅整理间距

只调整留白和字号无法解决新增与删除辨识度不足、计划状态过于平淡以及两个删除按钮争抢视觉权重的问题。

### 未采用：大色块或分步向导

大面积颜色会降低长仓库列表的可读性；向导会重新引入已移除的“下一步”，破坏一步提交。全屏或超宽弹窗也不适合桌面工具的短期确认任务。

## 视觉系统

实现只使用现有主题语义变量，以下 hex 仅定义设计角色，不写入组件：

- **Canvas** `#FFFFFF`：主体卡片和表单背景；映射当前主题 `background/card`。
- **Graphite** `#1F2328`：标题与主要数据；映射 `foreground`。
- **Slate** `#656D76`：说明、序号和次要数据；映射 `muted-foreground`。
- **Constructive** `#1A7F37`：新增操作标识；映射 `success/success-surface/success-border`。
- **Destructive** `#CF222E`：删除操作标识；映射 `danger/danger-surface/danger-border`。
- **Caution** `#9A6700`：必要审批和非阻断风险；映射 `warning/warning-surface/warning-border`。

应用支持多主题，组件不得硬编码这些 hex。所有主题通过既有 contract 提供同等角色。

字体不增加包或 Web Font：

- 标题与正文继续使用应用系统 UI 字体，标题使用 `font-semibold` 建立层级；
- 分支名、路径、步骤序号和依赖路径继续使用现有等宽字体；
- 辅助说明保持 `text-xs` 或 `text-[10px]` 的桌面工具密度。

视觉签名是“操作轨道”：模式化头部、编号栏头和执行清单形成一条从意图到结果的扫描路径。除此之外保持克制，不增加渐变、装饰插画或无业务意义的动画。

## 页面占用与响应式布局

### 桌面

- 保持现有 `sm:max-w-5xl`，约 64rem 上限；不升级到 6xl、全屏或固定像素宽度。
- 保持 `max-h-[85vh]`；弹窗不会覆盖全部工作区上下文。
- 主体保持约 `3:2` 双栏，右栏最小宽度 18rem。
- 头部与底部操作栏使用紧凑内边距；节省出的高度用于仓库列表和计划。
- 只有主体进入 `minmax(0, 1fr)`；长内容时左右栏各自滚动，头部和底部动作始终可见。
- 短内容不设置人为最小高度，弹窗随内容收缩，不留下大块空白。
- 双栏之间使用单一分隔线，不再用额外大间距制造两张悬浮卡片。

### 窄屏与紧凑窗口

- 按 `01 配置 → 02 执行清单` 单栏排列，共用纵向滚动；不制造嵌套横向滚动。
- 计划栏通过顶部边界与配置区分隔，不重复外层卡片。
- 底部按钮占满可用宽度并按次要动作在下、主动作在上的视觉顺序呈现。
- 分支名、路径和依赖路径允许断行或截断并保留 `title`，不能撑宽弹窗。

## 信息架构

```text
┌──────────────────────────────────────────────────────────────┐
│ [模式图标] 新增/删除子工作区                     [同步全部] │
│            一句明确说明                                      │
├──────────────────────────────┬───────────────────────────────┤
│ 01 选择与配置                │ 02 操作计划                   │
│    分支名称                  │    目标摘要 / 计划状态        │
│    仓库成员与依赖            │    执行步骤轨道               │
│    根目录条目                │    必要确认                   │
│                              │                               │
├──────────────────────────────┴───────────────────────────────┤
│                                      取消  [创建/删除]       │
└──────────────────────────────────────────────────────────────┘
```

### 模式化头部

- 新增显示 `FolderPlus` 图标、成功色图标容器、现有标题与描述。
- 删除显示 `Trash2` 图标、危险色图标容器、现有标题与描述。
- “同步全部仓库”继续只在新增出现，位置保持头部右侧，不占用配置列表行。
- 头部用浅语义底色与下边界标识操作类型；不使用大面积高饱和背景。

### 配置栏

- 栏头使用 `01`、标题和一句与模式相关的辅助说明。
- 新增保留分支、仓库、仓库依赖和根目录条目原有控件，只统一容器边界与间距。
- 删除把当前危险说明与两个分支选项组合成一个“删除范围”面板：上部说明不可逆影响，下部逐行选择本地/上游分支。
- 上游分支继续依赖本地分支选项；禁用态使用真实 `disabled`。

### 计划栏

- 栏头使用 `02`、标题和“随配置自动更新”的辅助说明。
- `incomplete` 使用中性清单图标和引导文案；`planning` 使用单一旋转图标；`error` 使用危险边界和错误图标。
- ready 状态继续展示服务端返回的步骤、仓库依赖与必要审批。
- 计划步骤使用紧凑序号轨道，序号只表达当前计划中的执行顺序；执行状态仍使用等待、进行中、完成和失败。
- 删除模式的目标摘要使用危险边界，但路径和分支仍保持中性高对比，避免整栏变红。
- “所有内容已满足”保留空计划语义，不伪造执行步骤。

### 底部操作栏

- 使用顶部边界和轻微中性背景与主体分离，不增加高度较大的阴影。
- 新增主按钮显示新增图标和“新增子工作区”；删除主按钮显示删除图标和“删除子工作区”。
- 普通删除保持危险实底，是删除流程的主要动作。
- “强制删除”改用现有 `destructive-soft` 危险描边样式，仍位于普通删除之前；它保持同等安全校验，但不与正常删除争抢主视觉。
- 执行中的 loading 图标替换静态模式图标，避免重复图标。

## 组件边界

### `OneStepPlanningLayout`

增加可选的操作控制台呈现参数，默认值保持当前 plain 行为，确保依赖维护、扩展和缩减不被视觉改造波及：

- `presentation?: 'plain' | 'operation-console'`；
- `tone?: 'constructive' | 'destructive'`；
- pane 可选 `step` 与 `description`。

布局组件只负责网格、边界、背景和栏头，不理解 create/remove 请求、计划或执行状态。

### `BranchWorkspaceDialog`

- 仅在 `mode === 'create' || mode === 'remove'` 时启用 operation-console；
- 选择对应 tone、模式图标、栏头辅助文案和底部动作样式；
- 继续拥有所有表单、计划映射和执行状态；
- 增加局部只读辅助组件渲染模式头部、删除范围和计划状态，不创建新的业务状态。

不拆出新的通用领域组件，也不修改 `Dialog`、`Button` 等全局 primitive 的默认外观。

## 状态、错误与动效

- 输入变化后仍立即隐藏过期计划并进入 planning；UI 优化不得保留旧清单作为视觉占位。
- 计划失败使用明确危险样式，但不改变错误恢复路径。
- 执行中锁定输入、审批与关闭入口；进度留在计划栏，避免跳转到另一页面。
- 删除执行失败继续显示强制删除和重试条件，不用视觉优化绕过安全门。
- 只使用既有 dialog 进入/退出动画和 loading 旋转；不增加计划行逐个飞入、脉冲背景或布局位移动画。
- 所有新增 transition 必须只改变颜色，并天然兼容 reduced motion。

## 可访问性与文案

- `01`、`02` 标记为装饰或与标题组合，不能替代真正的 heading。
- 模式图标和状态图标为装饰；标题、描述、状态文本提供完整语义。
- `aria-live="polite"` 继续只放在计划区域，规划完成不抢焦点。
- 危险和成功状态同时使用边界、图标和文本，不能只依赖颜色。
- 继续使用 sentence case；中文使用“子工作区”和“成员工作树”。
- 新增四组模式相关辅助说明，并在英文、简体中文、日文和韩文字典中保持键集合一致。

## 测试与验收

### 结构与视觉契约

- create/remove 使用 operation-console；extend/reduce 和依赖维护保持 plain。
- 新增头部具有 constructive tone、`FolderPlus` 图标和同步全部动作。
- 删除头部具有 destructive tone、`Trash2` 图标和删除范围面板。
- operation-console 主体保持 `sm:max-w-5xl`、`max-h-[85vh]`、桌面 `3:2` 双栏与窄屏单栏。
- 两栏显示 `01`、`02`、模式说明和合法 heading。
- 未就绪、规划中和错误状态具有不同图标与语义样式。
- 删除目标摘要具有危险边界；普通删除为 destructive，强制删除为 destructive-soft。
- 紧凑底部按钮可占满宽度，长路径不会造成横向滚动。

### 行为回归

- 自动规划请求次数、请求内容和取消语义不变。
- 当前计划匹配、审批门、计划令牌、提交、重试和强制删除安全规则不变。
- 新增仓库依赖选择和右栏依赖清单不变。
- 执行进度与失败恢复测试继续通过。
- 四语言字典键一致。

### 验证

- 运行目标 Vitest；
- 运行 `bun run typecheck`；
- 运行 `bun run check:architecture`；
- 运行 `bun run test`；
- 在可用环境中检查桌面和窄屏渲染，确认无横向滚动、无内容截断和无不合理空白。

## 工程原则

- **KISS**：一个现有弹窗、一个可选布局呈现，不新增流程或状态。
- **YAGNI**：不增加主题、字体、全屏模式、用户可选布局或动画系统。
- **DRY**：新增和删除复用同一操作控制台骨架，模式差异由 tone 与现有文案表达。
- **SOLID**：布局组件只拥有视觉结构；弹窗继续拥有领域状态；服务端继续拥有权威计划。
- **安全**：所有视觉变化都围绕现有计划和审批展开，不降低删除保护。
