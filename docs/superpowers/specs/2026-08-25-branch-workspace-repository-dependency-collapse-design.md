# 子工作区仓库依赖折叠摘要设计

**日期**：2026-08-25
**状态**：已实施

## 目标

在新增子工作区或增加成员工作树时，用户完成某个仓库的仓库依赖选择后，可以手动收起候选树。收起状态不再显示未选候选，只显示已勾选的相对路径及其复制或软链接方式，从而减少一步式弹窗左栏的纵向占用，同时保留随时展开修改的能力。

## 范围

本次只覆盖 `BranchWorkspaceDialog` 中为新成员工作树选择仓库依赖的区域：

- 新增子工作区；
- 增加成员工作树。

以下流程不变：

- 单仓库创建工作树的 `CreateWorktreeDialog`；
- 工作区根目录级子工作区依赖的添加和移除弹窗；
- 修复、缩减、删除和批量 Git 操作；
- 仓库依赖来源、选择模型、复制/软链接协议、计划令牌和服务端校验。

“仓库依赖”继续表示 `CONTEXT.md` 中的 branch-workspace repository dependency selection：它属于一个待创建的成员工作树，不是工作区根目录级子工作区依赖。本设计不新增领域术语，因此不修改 `CONTEXT.md`。

## 交互设计

### 展开状态

- 仓库依赖开关开启后，依赖来源选择器和依赖候选树按现状显示。
- 初始状态始终展开。
- 未选择任何依赖时不提供收起动作，避免产生没有信息的空摘要。
- 选择至少一项后，区域标题旁显示“收起已选依赖”按钮。
- 用户可以继续展开目录、勾选路径和修改每项的复制/软链接方式。

### 收起状态

- 依赖来源选择器继续可见，使当前选择来源保持明确。
- 完整候选树在视觉和可访问性树中隐藏。
- 摘要只列出当前已勾选项；不显示未选候选、空目录或目录加载状态。
- 每行显示完整相对路径和只读方式标签“复制”或“软链接”。
- 摘要顺序沿用受控 `selections` 的稳定顺序，不另做排序。
- 原位置显示“展开修改”按钮，点击后恢复完整候选树和原有勾选、目录展开及方式选择状态。

### 重置规则

- 切换依赖来源会清空现有选择并自动恢复展开。
- 关闭仓库依赖开关会卸载该选择区；再次开启时默认展开。
- 如果外部状态使选择变为空，自动恢复展开。
- 不因新增或删除某一个选择自动收起；收起只由用户显式触发。
- 多个仓库的折叠状态彼此独立。

### 执行状态

执行期间继续锁定来源、勾选框和方式选择。折叠/展开属于只读展示动作，可以继续使用，便于用户查看已提交选择；它不改变请求或审批。

## 组件边界

新增一个位于 `src/web/components/repo-workspace/` 的子工作区专用仓库依赖选择组件。该组件：

- 组合现有 `WorktreeBootstrapSourcePicker` 和 `WorktreeDependencyTree`；
- 接收来源、来源选项、受控 selections、disabled、读取 pending 和变更回调；
- 只拥有 `collapsed` 这一短期 UI 状态；
- 在来源变化或 selections 变空时恢复展开；
- 使用稳定的 `aria-expanded`、`aria-controls` 和可见按钮文案。

`BranchWorkspaceDialog` 继续拥有每个仓库的来源、选择和读取 pending 状态。新组件不理解计划请求、仓库选择、自动规划或执行 mutation。

不把折叠能力直接加入共享 `WorktreeDependencyTree`：该树同时服务单仓库创建工作树，树的职责是延迟读取和编辑候选，而不是决定某个宿主弹窗的摘要交互。

## 渲染与数据流

```text
BranchWorkspaceDialog
  repositoryBootstrapSources[name]
  repositoryBootstrapSelections[name]
  repositoryDependencyReadPending[name]
              │
              ▼
BranchWorkspaceRepositoryDependencySelection
  local: collapsed
  visible: source picker + (tree OR selected-only summary)
              │
              ▼
WorktreeDependencyTree
  lazy directory reads + controlled selection edits
```

候选树在收起时保持挂载，通过 `hidden` 容器从视觉和可访问性树中移除，而不是条件卸载。这样可以保留已加载目录与展开状态，也不会因重新挂载重复读取文件树或短暂改变 `onPendingChange`。

折叠状态不参与 `BranchWorkspacePlanRequest`、latest-plan 请求身份或本地计划修订号。只有 selections、来源或其他既有业务输入变化才触发自动规划。

## 错误与边界

- 候选树读取失败时仍按现有方式在展开状态显示错误和重试；没有有效选择时不能收起错误区域。
- 已收起后发生后台读取失败不会把摘要替换为错误页；展开后显示现有错误状态。
- 选择目录继续表示一个依赖，不展开为所有后代；摘要只显示该目录路径一次。
- 选择祖先导致后代选择被替换时，摘要立即投影最新受控 selections。
- 符号链接候选仍不可选择，不会进入摘要。
- 长路径使用可换行或截断加 title 的方式保持窄屏无横向滚动。

## 可访问性与文案

- 折叠按钮使用原生 `button`，暴露 `aria-expanded` 和指向候选树容器的 `aria-controls`。
- 收起后候选树使用 `hidden`，避免键盘焦点进入不可见控件。
- 按钮文案使用“收起已选依赖”与“展开修改”。
- 摘要区域使用列表语义；路径保持等宽字体，方式标签有可读文本而不只依赖颜色。
- 英文、简体中文、日文和韩文字典保持键集合一致。

## 测试与验收

### 聚焦组件

- 初始展开，零选择时没有收起动作。
- 有选择时可以收起，候选树变为 hidden，摘要只显示已选路径和方式。
- 收起不调用 selections、pending 或来源变更回调。
- 展开后保留已加载目录、目录展开、勾选和方式状态，不重复读取根目录。
- selections 变空或来源变化时自动展开。
- disabled 时业务控件锁定，但折叠/展开仍可查看。

### 子工作区集成

- 新增子工作区和增加成员工作树均使用折叠区。
- 多仓库折叠状态相互独立。
- 收起前后构造的仓库依赖请求完全一致。
- 收起动作不发起新的自动计划；实际选择或方式变化仍按现有规则重规划。
- 关闭依赖开关再打开时选择为空且默认展开。

### 回归

- `WorktreeDependencyTree` 的延迟加载、祖先/后代选择和默认复制行为不变。
- `CreateWorktreeDialog` 的依赖树行为不变。
- 四语言字典键一致。
- 运行目标 Vitest、`bun run typecheck`、`bun run check:architecture` 和 `bun run test`。

## 方案取舍

### 采用：子工作区专用组合组件

它把折叠摘要限制在用户指定入口，并让 `BranchWorkspaceDialog` 保持业务状态所有权。共享树继续专注候选读取与选择，符合单一职责。

### 未采用：给共享依赖树增加 collapsible/summary props

这会让单仓库创建工作树默认获得未请求的交互，并把宿主布局决策塞入通用树组件。即使增加开关参数，也会扩大共享 API 和测试矩阵。

### 未采用：直接在 BranchWorkspaceDialog 内维护折叠 Map 和摘要 JSX

改动文件较少，但会继续增大已经复杂的弹窗，并把同一仓库依赖区域拆散在来源、树、摘要和重置分支中。一个窄职责组合组件更容易独立验证。

## 工程原则

- **KISS / YAGNI**：只增加手动折叠和已选摘要，不增加搜索、持久化、自动收起或服务端字段。
- **DRY**：复用现有来源选择器、依赖树、选择模型和方式文案。
- **SOLID**：弹窗拥有业务输入，组合组件拥有展示折叠，依赖树拥有目录读取与选择编辑。
- **安全**：折叠不改变请求、计划、审批或执行，只改变当前弹窗的可见投影。

该决定局部、可逆且没有跨边界协议取舍，不创建 ADR。
