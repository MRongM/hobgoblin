# 子工作区批量错误隔离与 AI 托管设计

**日期**：2026-07-31  
**状态**：已确认，授权内联自主实施

## 目标

分支工作区的批量提交、批量拉取、批量推送、批量合入和批量合出在单个仓库成员失败后继续处理其他成员。全部可执行成员结束后，前台一次性展示失败汇总，并允许用户选择 Codex 或 Claude，把所有失败作为一个 AI 任务预填到分支工作区根终端。

## 语义边界

- “不阻断”只适用于已经定位到某个仓库成员的 Git、工作树准备或清理失败。
- 计划令牌错误、执行输入错误、全局计划校验失败、成员清单漂移、整批 readiness 失败仍在任何 Git 写入前阻断。
- 用户取消仍尽快停止；批量合出的应用临时工作树先完成既有安全清理，再返回取消结果。
- 成员始终按清单顺序串行执行，不并行，不提供跨仓库事务，也不回滚已完成写入。
- 批量合出只有在当前成员的临时工作树清理已经结算后才进入下一成员；清理失败本身作为该成员的最终失败记录。

## 方案比较

### 采用：服务端逐成员 best-effort，Renderer 汇总后显式 AI handoff

服务端写路径为一次执行维护局部失败映射。成员成功进入现有 `completed` 集；成员失败写入映射并继续。循环结束后，结果按原计划顺序投影全部 `succeeded`、`failed`、`satisfied` 和未选择成员。相同计划重试继续跳过成功成员，重试所有失败成员，并沿用既有合并步骤恢复状态。

Renderer 从权威执行结果筛选失败成员，并与仍在前台的计划组合出仓库名、成员工作树、失败步骤、诊断、失败原因和保留的冲突现场。一个 AI handoff 命令承载完整列表，在分支工作区根终端中预填，等待用户检查并手动执行。

该方案把跨仓库执行策略留在服务端写层，把终端导航与短期交互留在 Renderer，符合现有分层；结果协议已经是逐成员数组，只需扩展其使用方式，不引入持久状态、后台任务或新依赖。

### 不采用：Renderer 在首次失败后重规划并逐个补跑

这会让 UI 接管计划令牌、完成集和部分合并进度，且首次请求仍然无法满足“不阻断”。网络中断或界面关闭还会丢失协调语义。

### 不采用：每个失败成员自动启动一个 AI 进程

该行为会产生多个终端任务，无法为所有批量动作推断唯一提供方，并绕过现有“命令只预填、不自动执行”的安全边界。单个汇总任务更容易审阅，也能跨成员判断共同根因。

## 结果模型与重试

一次执行中的失败记录包含：

- `repositoryName`：稳定的成员身份；
- `step`：`commit`、`prepare`、`pull`、`merge`、`push` 或 `cleanup`；
- `message` 与可选 `reason`：底层诊断；
- 可选 `conflictWorktree`：只有仍实际保留的冲突现场才存在。

结果顶层 `ok` 在任一成员失败时为 `false`，`message` 使用统一的“部分成员失败”文案；具体根因必须从所有失败成员读取，不能再把首个错误当成整批结果。

`completed` 只记录成功成员，因此失败成员在相同执行身份下可重试。一次重试产生新的失败汇总，不保留已经恢复的旧错误。合并成员的已拉取、已合并或已推送步骤继续使用现有 `mergeProgress`；成员完成后清除进度。

## 合并与清理

批量合入的现有成员工作树可能保留冲突。该失败被记录后继续下一个仓库；AI 汇总中包含精确冲突路径。

批量合出复用现有目标工作树时同样可以保留冲突。使用应用临时工作树时，无论合并步骤成功还是失败，都先尝试清理临时工作树：

- 清理成功：记录原步骤失败，临时路径不作为冲突现场；
- 清理失败：以 `cleanup` 作为该成员最终失败，保留服务端已有临时工作树状态供重试清理；
- 用户取消：完成该成员清理后停止，不继续后续成员。

## AI 托管交互

任何批量 Git 结果包含至少一个 `failed` 成员时，原面板或弹窗显示一个“批量错误 AI 托管”区域，提供当前可用的 Codex 与 Claude 按钮。它取代仅针对第一个保留冲突的专用入口，覆盖普通提交、拉取、推送、准备、合并和清理错误。

点击提供方后：

1. 复用现有分支工作区根终端；没有可用会话时创建一个。
2. 构建一个结构化提示，列出批量动作类型及所有失败成员。
3. 对每个成员列出仓库名、目标成员工作树、失败步骤、诊断、原因和可选冲突工作树。
4. 提示 AI 先检查现场并做最小修复，不执行 `git add`、`git commit`、`git push`、`git merge --continue` 或破坏性 Git 命令。
5. 仅写入终端输入，不发送换行；成功后关闭原面板，失败则保留面板和提供方按钮。

提供方可用性探测、pending 和预填错误继续复用现有 AI handoff 组件；分支工作区内新增通用的批量错误汇总包装层，避免复制提供方逻辑。

## 状态与分层

- `src/server/modules/branch-workspace-git-action-write-paths.ts` 拥有逐成员失败隔离、临时工作树清理、完成集和结果聚合。
- `src/shared/branch-workspace-git-actions.ts` 继续定义权威结果协议，不持有 UI 专属命令文本。
- `BranchWorkspaceGitActionPanel` 只把当前计划与结果投影为错误汇总输入。
- `WorkspaceRepositoryRail` 拥有分支工作区根终端导航和 AI 命令预填。
- 托管 pending/error 属于一次界面交互的 Local state；不进入 Zustand、服务端持久化或会话恢复。

## 测试与验收

1. 批量提交首个成员失败时仍提交后续成员，并在一个结果中返回全部失败。
2. 批量拉取和推送分别验证失败隔离、清单顺序和仅重试失败成员。
3. 批量合入在普通错误及保留冲突后继续其他成员，且保留每个失败步骤。
4. 批量合出在准备、Git 步骤和清理失败后结算当前临时工作树，再继续后续成员。
5. 用户取消不继续后续成员。
6. 进度投影能同时标记多个失败成员，成功计数只包含成功成员。
7. 所有批量动作的失败结果都显示一个通用 AI 托管区域。
8. handoff 输入和终端命令包含每个失败成员、工作树、步骤与诊断；保留冲突额外包含冲突路径。
9. handoff 仅预填不执行，成功关闭、失败留在原界面。
10. 四种语言字典一致，术语文档不再声称批量 Git 在首个成员失败后停止。
11. `bun run typecheck`、`bun run check:architecture`、目标测试与全量 `bun run test` 完成验证。

## 非目标

- 不让 AI 自动执行、自动选择提供方或后台接管。
- 不自动解决冲突、暂存、提交、继续合并或推送。
- 不改变非 Git 的分支工作区创建、扩展、缩减、修复、删除和依赖维护语义。
- 不并行执行仓库成员，不新增自动回滚、持久失败队列或跨启动恢复。
