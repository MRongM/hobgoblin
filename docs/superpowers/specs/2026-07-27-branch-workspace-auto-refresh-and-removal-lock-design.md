# 子工作区自动状态刷新与前台删除设计

**日期**：2026-07-27  
**状态**：已确认

## 目标

1. 子工作区首次显示“需要修复”时，自动执行一次现有“清除缓存”动作对应的定向状态重读。
2. 删除子工作区时，在确认弹窗内显示现有步骤进度；删除完成前弹窗不得关闭或转为后台操作。

## 自动状态刷新

`WorkspaceRepositoryRail` 只观察成功查询结果中处于
`needs-action / repair / drift` 的子工作区。每个子工作区在一次连续漂移状态中只触发一次根级
`branchQuery.refresh()`：

- 多个新漂移项同时出现时合并为一次刷新。
- 刷新后仍漂移时停止，不循环重试。
- 项目恢复正常后清除本次尝试记录；以后再次漂移可再刷新一次。
- 创建中断、继续减少、继续删除和查询错误不触发。
- 自动刷新失败时保留当前状态和手动“清除缓存”入口。

该动作只重读服务端权威状态并更新 TanStack Query 缓存，不执行修复，也不清空
`localStorage`、`sessionStorage` 或仓库恢复缓存。

## 前台删除弹窗

删除计划预览保持现状。用户确认删除或重试删除后，弹窗进入执行锁定状态：

- 继续使用现有实时快照和步骤投影显示等待、进行中、完成、失败及完成数。
- 隐藏右上角关闭按钮，阻止 Esc 和遮罩点击关闭，并禁用取消按钮。
- 成功响应返回后才关闭弹窗；用户回到页面时子工作区已经删除完成。
- 失败时停止锁定，弹窗保持打开，展示错误与已完成进度，并允许重试或关闭。

底层服务端仍按现有异步顺序执行并发布失效事件，以保证 Renderer 可以持续显示进度；本次只禁止把已确认的删除操作转入后台。创建、扩展、减少、修复、服务端中止接口和恢复协议不变。

## 实现边界

- 自动刷新逻辑保持在 `WorkspaceRepositoryRail`，不让查询读层隐式发起二次读取。
- 删除执行锁定保持在 `BranchWorkspaceDialog` 的本地交互状态中，不新增服务端字段或 API。
- 复用 `branchQuery.refresh()`、现有删除请求和 `projectBranchWorkspaceOperationProgress()`。
- 不新增依赖，不修改全局对话框默认行为。

## 错误与安全

- 自动刷新不改变文件、工作树、分支或注册表。
- 删除的既有审批、安全检查、顺序执行、失败停止和恢复语义不变。
- 网络或服务端失败会解除弹窗锁定并保留失败状态，不把失败伪装成成功。
- 应用或服务进程意外退出仍由既有“删除未完成”恢复路径处理；正常 UI 交互不再主动制造该状态。

## 测试

### 自动刷新

- 首次漂移自动刷新一次，持续漂移不重复刷新。
- 多个漂移项合并为一次刷新。
- 恢复正常后再次漂移可再次刷新。
- 创建中断及其他生命周期状态不刷新。
- 刷新拒绝后不循环，并保留手动入口。

### 删除弹窗

- 删除执行期间显示现有进度且关闭按钮不可用。
- Esc、遮罩点击、右上角关闭和取消均不能关闭执行中的删除弹窗。
- 成功完成后弹窗关闭。
- 失败后弹窗保持打开、解除锁定并允许重试或关闭。
- 其他弹窗模式的关闭和取消行为不变。

### 验证

运行针对性 Vitest、`bun run typecheck`、`bun run check:architecture` 和 `bun run test`。

## 非目标

- 自动执行子工作区修复。
- 清空全局浏览器存储。
- 把删除改成阻塞 Renderer 线程的同步 I/O。
- 修改删除计划、服务端进度协议或删除恢复模型。
- 调整创建等其他生命周期操作的取消语义。

## 决策记录

不创建 ADR：两项改动都复用现有查询与生命周期边界，属于局部且可逆的交互调整。
