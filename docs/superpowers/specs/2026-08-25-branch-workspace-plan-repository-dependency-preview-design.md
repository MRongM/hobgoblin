# 子工作区操作计划仓库依赖预览设计

**日期**：2026-08-25
**状态**：已实施

## 目标

在新增子工作区或增加成员工作树的一步式弹窗中，让右侧“操作计划”明确展示每个待创建仓库已经纳入计划的仓库依赖，包括相对路径及复制或软链接方式，使用户在一次提交前可以核对实际执行内容。

## 范围

- 覆盖 `BranchWorkspaceDialog` 中 `create-worktree` 计划步骤，因此同时适用于新增子工作区和增加成员工作树。
- 只展示服务端返回的 `BranchWorkspaceRepositoryPlan.worktreeBootstrap`，不读取左侧正在编辑但尚未形成新计划的临时状态。
- `worktreeBootstrap.kind === 'materialize'` 且存在 selections 时显示；`skip` 或空 selections 不显示额外区域。
- 修复、缩减、删除、单仓库创建工作树及工作区根目录级依赖弹窗不变。
- 不修改 IPC、服务端计划、执行协议、审批规则或计划令牌。

## 交互与视觉

依赖预览嵌套在对应仓库的“创建工作树”步骤下方，与现有创建来源和同步意图放在同一仓库上下文内：

- 标题复用“仓库依赖”；
- 每个已选依赖显示只读勾选标记、完整相对路径以及“复制”或“软链接”标签；
- 不展示未选候选，也不提供编辑控件；
- 长路径允许断行并通过 `title` 保留完整内容；
- 计划为空、跳过依赖或没有选择时不渲染空容器。

进度状态仍位于计划步骤右侧；依赖列表位于左侧内容区，避免与执行状态互相挤压。

## 数据与一致性

```text
服务端 BranchWorkspacePlan
  repositories[repositoryName].worktreeBootstrap
                    │
                    ▼
对应 create-worktree step
  创建来源 + 同步意图
  仓库依赖：勾选路径 + materialize mode
```

右栏必须绑定 `displayedPlan`。左侧改变来源、路径或方式后，在自动规划返回前继续显示旧计划；新计划返回后整体替换。这与现有 latest-plan 和计划令牌语义一致，确保用户看到的内容就是当前可提交计划，而不是尚未校验的请求草稿。

## 组件边界

在 `BranchWorkspaceDialog.tsx` 内增加窄职责的 `BranchWorkspaceRepositoryDependencyPreview`：

- 输入仅为 `BranchWorkspaceRepositoryPlan`；
- 只投影现有计划，不拥有状态、不发请求、不修改选择；
- 与同文件现有 `BranchWorkspaceCreationSourcePreview` 保持相同局部辅助组件模式。

当前需求只在一个宿主中使用，拆分新文件或扩展共享依赖树都会扩大 API，暂不采用。

## 可访问性

- 依赖区域使用带可读名称的分组语义；
- 条目使用列表语义；
- 勾选图标为装饰，路径和方式文本提供完整语义；
- 颜色不作为选择或方式的唯一表达。

## 测试与验收

- `materialize` 计划展示所有已选路径及各自复制/软链接方式。
- 预览位于对应 `create-worktree` 步骤中，标题为“仓库依赖”。
- `skip` 计划不展示依赖区域。
- 现有创建来源、同步意图、步骤进度与一步式提交行为不变。
- 通过目标 Vitest、Prettier、`bun run typecheck`、`bun run check:architecture` 和完整 `bun run test`。

## 方案取舍

### 采用：绑定权威计划并嵌套到仓库步骤

这能保持仓库归属和提交一致性，也不引入额外状态。

### 未采用：镜像左侧实时选择

自动规划存在异步窗口，实时选择可能尚未被服务端接受；右栏若提前变化，会失去“确认实际计划”的含义。

### 未采用：右栏增加独立的全局依赖区

它会重复仓库名称并弱化依赖与创建步骤的关系，多仓库时也更难扫描。

## 工程原则

- **KISS / YAGNI**：只增加只读计划投影，不增加编辑、折叠、持久化或新协议。
- **DRY**：复用现有计划模型、创建步骤查找和四语言文案。
- **SOLID**：左栏组件负责编辑，服务端负责计划，右栏辅助组件只负责呈现。
- **安全**：不改变执行数据；空值和跳过决策安全地渲染为空。

该决定局部、可逆且没有新的跨层协议，不创建 ADR，也不修改 `CONTEXT.md`。
