# 仓库分支双向合并设计

**日期**：2026-07-28
**状态**：已实现并验证

## 背景

普通工作树分支目前只有一个“合并”动作。它在该分支的工作树目录执行 `git merge <所选分支>`，语义实际是把所选来源分支合并到操作分支。方向没有出现在名称中，也无法从操作分支把提交安全地合并到另一个本地分支。

项目已经为子工作区批量合出实现了目标分支选择、现有目标工作树校验、未检出目标的应用临时工作树、拉取—合并—推送管线及冲突清理。普通分支动作应遵循同一安全规则并复用稳定的仓库 Git 原语与临时路径所有权工具，但不应依赖或重构正在演进的子工作区清单、批次顺序、重试与成员领域模型。

## 目标

1. 把现有普通分支“合并”明确命名为“合并入”。
2. 新增“合并出”，把操作分支的已提交历史合并到用户选择的本地目标分支。
3. 目标分支已有干净工作树时直接使用；未检出时使用应用临时工作树；已有脏工作树时禁止执行。
4. 两个方向都保留“仅合并”和目标分支拥有可用上游时的“拉取、合并并推送”能力。
5. 合并冲突只保留在现有目标工作树；临时工作树中的冲突在报告后清理。
6. AI 接管始终面向实际冲突工作树，只复用 `open` 内部终端；没有已打开终端时自动创建一个，再填入可审阅但不执行的命令。

## 非目标

- 不支持远端跟踪引用作为合并来源或目标；候选必须是现有本地分支。
- 不自动推断目标分支，不记忆上次目标分支，也不从默认分支、上游或创建来源推导目标。
- 不把未提交工作树内容带入合并，不自动提交或暂存。
- 不提供 rebase、squash、no-ff 或合并策略选项。
- 不自动解决冲突，不自动执行 AI 命令、`git add`、`git commit` 或 `git merge --continue`。
- 不改变子工作区批量合并的用户交互、顺序执行或重试语义。

## 领域语义

### 合并入

“合并入”保留现有行为：操作分支是目标，用户选择另一个本地分支作为来源。

```text
所选来源分支 ──merge──> 操作分支工作树
```

- Git 写入发生在操作分支的工作树。
- 普通合并冲突保留在该工作树，并可从该现场发起 AI 接管。
- “拉取、合并并推送”中的拉取与推送都作用于操作分支。
- 本次功能不改变现有来源候选和 Git 对目标工作树未提交改动的判断方式。

### 合并出

“合并出”反转方向：操作分支是来源，用户选择另一个本地分支作为目标。

```text
操作分支已提交历史 ──merge──> 所选目标分支工作树
```

- 操作分支必须拥有工作树，且执行前该来源工作树必须干净。
- 未提交内容不属于来源；来源工作树脏时菜单动作禁用，服务端仍进行权威复检。
- 目标分支不能等于来源分支。
- 目标分支选择是弹窗本地状态，不持久化。

## 目标分支规则

服务端计划列出除来源分支外的全部本地分支，并为每个候选给出当前可执行性：

| 目标状态 | 是否可选 | 执行位置 | 冲突现场 |
|---|---:|---|---|
| 已在干净普通工作树中检出 | 是 | 该现有工作树 | 保留在该工作树 |
| 未被任何工作树检出 | 是 | 应用临时工作树 | 报告后清理，不保留 |
| 已在脏工作树中检出 | 否 | 无 | 无 |
| 工作树状态不可读 | 否 | 无 | 无 |
| 锁定的应用临时工作树 | 否 | 无 | 无 |
| 可识别的未锁定遗留应用临时工作树 | 是 | 先清理，再创建 | 报告后清理，不保留 |

目标选项只展示分支名和不可用原因，不暴露应用临时工作树路径。

## 远端管线

两个方向都支持：

- **仅合并**：直接执行目标工作树中的合并。
- **拉取、合并并推送**：拉取目标分支上游，合并来源分支，再推送目标分支。

“合并出”的远端能力完全属于所选目标分支：

- 只有目标分支存在可用上游时，远端模式才可用。
- 来源分支是否有上游不影响远端模式。
- 拉取完成后、执行合并前，服务端重新验证来源分支提交与干净状态没有变化。
- 任一步失败即停止；已经完成的拉取、合并提交或远端推送不回滚。

## 交互设计

普通工作树分支菜单在同一动作组中显示两个并列动作：

- **合并入**：打开来源分支选择弹窗。
- **合并出**：打开目标分支选择弹窗。

不增加方向选择中间页。现有快捷动作持久标识 `merge` 继续代表“合并入”，所以升级后原有快捷动作自然保持原行为；“合并出”使用新的 `mergeOut` 标识并可独立成为快捷动作。

“合并出”弹窗：

- 打开时从服务端读取一次权威计划。
- 显示来源分支为只读上下文，并要求选择一个目标分支。
- 脏或不可用目标保持可见但禁用，并显示原因。
- “仅合并”在选中可用目标后启用。
- “拉取、合并并推送”始终可见，但在目标没有可用上游时禁用并解释原因。
- 计划过期时不自动重试 Git 写入；刷新候选并要求用户重新审阅后再提交。
- 成功后关闭；失败后保留错误与选择。

四种语言使用方向明确、符合各自语言习惯的文案。中文菜单名称严格使用“合并入”和“合并出”；英文不直译为含糊的 `Merge out`，而使用 `Merge into this branch` 与 `Merge this branch into…`。

## 冲突与 AI 接管

### 合并入冲突

冲突现场仍是操作分支工作树。现有 AI 接管使用该分支与路径。

### 合并出冲突

- 现有目标工作树：结果携带权威的 `{ branch, path }` 冲突现场，弹窗显示 AI 接管。
- 应用临时工作树：服务端强制移除临时工作树并仅返回冲突错误，不返回可接管现场。
- 来源工作树永远不是冲突现场。

### 终端选择

AI 接管使用共享终端命令桥：

1. 导航到冲突分支的终端页并展开详情区。
2. 从该工作树会话中优先选择当前 `open` 终端，否则选择第一个 `open` 终端。
3. 没有 `open` 终端时创建新的 Native 内部终端。
4. 向终端输入命令文本，但不附加回车，因此不会自动执行。

`opening`、`restarting`、`closed` 和 `error` 会话不视为可复用的已打开终端，避免文本被写入不可写会话后静默丢失。

## 服务端协议

### 计划

`POST /api/repo/merge-out-plan` 接收：

```ts
interface RepositoryBranchMergeOutPlanRequest {
  repoId: string
  sourceBranch: string
  sourceWorktreePath: string
}
```

成功结果包含来源提交、来源就绪状态、目标候选和计划令牌。令牌绑定：

- 仓库、来源分支与来源工作树身份；
- 来源 HEAD 与规范化工作树状态；
- 可选本地目标分支的身份集合。

令牌不把目标分支最新提交或上游状态锁死；执行前对所选目标重新读取并验证。这允许正常的目标分支更新，同时防止来源在用户确认后静默变化。

### 执行

`POST /api/repo/merge-out` 接收：

```ts
interface RepositoryBranchMergeOutExecuteInput {
  repoId: string
  planToken: string
  sourceBranch: string
  sourceWorktreePath: string
  destinationBranch: string
  mode: 'merge' | 'pull-merge-push'
}
```

服务端重新构建计划并验证令牌、来源干净状态、目标存在性、目标工作树状态和目标上游能力。客户端不提交目标工作树路径，执行位置始终由服务端解析。

冲突结果兼容普通 `ExecResult`，并仅在冲突现场被保留时附带：

```ts
interface RepositoryBranchMergeOutConflictWorktree {
  branch: string
  path: string
}
```

## 临时工作树安全

仓库级临时路径构造器生成与仓库同级的确定性路径：

```text
.hobgoblin-merge-out-<repository>-<16-hex>
```

- 路径哈希绑定仓库、计划令牌和目标分支。
- 只把父目录、仓库名前缀和固定十六进制后缀全部匹配的路径视为应用所有。
- 创建时跳过 repository bootstrap。
- 成功、失败和取消后都尝试强制移除临时工作树，但绝不删除目标分支。
- 普通用户工作树永不进入自动清理路径。
- 通用路径构造与所有权判断由仓库级模块拥有；子工作区批量合出通过自己的 `batch-merge` 命名空间复用，保留现有路径格式。

## 分层与状态所有权

- `src/shared/`：协议、计划/结果类型、严格输入规范化。
- `src/server/modules/` 计划层：读取仓库快照和状态，生成来源指纹与目标候选。
- `src/server/modules/` 写层：执行复检、目标准备、拉取、合并、推送和清理。
- `src/server/routes/`：只解析请求并委托。
- `src/web/`：保存弹窗选择、投影计划、调用执行接口、展示冲突现场。
- AI 终端选择继续由共享 `ai-terminal-handoff` 负责，不在合并弹窗复制终端会话逻辑。

计划与执行事实是 server-owned runtime truth；弹窗选择和错误是 renderer-local interaction state。不增加全局 store、持久目标分支、轮询、Electron 专用 API 或新依赖。

## 兼容性

- 现有 `/api/repo/merge`、`mergeRepositoryBranch()` 和操作历史 `kind: 'merge'` 保持为“合并入”。
- 现有持久快捷动作值 `merge` 无需迁移，升级后对应“合并入”。
- 新 `mergeOut` 仅用于 Renderer 动作标识；协议使用完整的 `merge-out` 名称。
- 子工作区批量合并协议与用户文案保持不变。

## 测试策略

- 共享协议：接受合法计划/执行输入，拒绝空值、控制字符、同源同目标、未知模式。
- 计划：来源必须对应干净工作树；候选覆盖干净现有、未检出、脏、不可读和遗留临时工作树；令牌只绑定约定事实。
- 临时路径：本地与 SSH 路径正确；拒绝仓库父目录外、错误仓库名、错误后缀和普通工作树。
- 写路径：现有/临时目标、远端模式顺序、拉取后来源复检、目标上游校验、每个失败阶段、冲突现场返回、临时清理和普通工作树保留。
- 路由/客户端：请求字段和 AbortSignal 透传正确。
- Renderer：两个菜单动作、旧快捷动作兼容、脏来源禁用、目标状态、按钮能力、计划过期刷新、冲突 AI 目标。
- AI 接管：复用打开终端；关闭/错误会话不复用；无打开终端时创建；写入不带回车。
- 文案：中英日韩键完整，中文严格使用“合并入/合并出”。
- 全量：`bun run typecheck`、`bun run test`、`bun run check:architecture`、`git diff --check`。

## 架构压力检查结论

- **方向无歧义**：操作目标、来源与目标分支在协议和文案中显式表达，不使用“当前分支”推断。
- **安全边界明确**：客户端不决定执行路径；服务端复检来源和目标，并只清理可证明为应用所有的临时工作树。
- **状态所有权正确**：交互选择留在弹窗，计划和 Git 事实由服务端读取。
- **DRY**：临时工作树所有权、Git 写原语和 AI 终端逻辑复用稳定的仓库级能力；普通动作不复制子工作区批次状态机。
- **KISS/YAGNI**：只提供两种方向与现有两种执行模式，不增加策略选项、默认目标或持久偏好。
- **故障可解释**：冲突现场、已完成写入不回滚和临时现场清理都有明确规则。

不创建 ADR：该设计是仓库分支动作的可逆功能扩展，复用既有合并安全模型，没有形成跨功能、难以逆转且需要长期解释的平台决策。
