# 工作区定向刷新与分批定时刷新

日期：2026-10-28。用户已确认刷新范围，允许实施。

- “刷新文件夹”提升至 More 和右键菜单的一级首项；保留忙碌、禁用和去重行为。
- 手动刷新指定子工作区时，重新发现其当前成员，并读取对应 Git 仓库的分支快照和 worktree status。成员可以是关联 worktree、独立仓库，或文件夹自身就是一个 Git worktree；按实际 repositoryId 去重。新发现的独立仓库必须先投影到 store，才能刷新。
- 顶部工作区重扫和子工作区列表刷新只更新结构和分支信息，不读取全部成员的改动数量。原有改动数量保留至定向刷新或分批定时刷新。
- 自动发现子工作区成员只启动分支快照读取，不能隐式触发全体 status。
- 定时刷新只处理活动项目，包含已配置仓库和子工作区发现的独立仓库；每个间隔最多刷新 5 个可用 Git 仓库，循环轮转，批次未完成时跳过新一轮。使用执行时的实例 token，失败不阻止后续轮转。
- 复用既有 server API、snapshot/status 协调和错误保留语义。不新增 Git 网络操作、持久状态或 realtime 协议。

采用现有刷新入口的定向调整；相比新增调度服务或只刷新当前选中仓库，该方案同时保持各成员最终更新和有界的周期负载。

验证覆盖一级菜单（More/右键）、混合成员和新成员投影、整体刷新不读 status、批次大小/轮转/失败/防重叠/切换项目，并运行类型检查、架构检查和完整测试。现有失败与改动前基线对照。
