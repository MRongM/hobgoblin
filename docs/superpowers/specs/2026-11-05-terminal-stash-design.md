# 终端收纳设计

## 目标

在项目、子工作区和工作树中，允许将暂时不用的终端从标签栏收纳起来，并从固定入口找回。收纳只是界面状态，不关闭终端、不结束进程，也不改变终端的输入权限。

## 交互

- 终端标签右键菜单提供“收纳终端”。
- 终端区域右上角固定显示三个点，打开当前项目的已收纳终端列表；列表覆盖该项目下的工作区和工作树，并标识终端所属位置。
- 选择列表项将终端移出收纳、切换到其所属位置并选中该终端。空列表显示明确的空状态。
- 收纳当前终端时，优先切换到同一位置的其他可见终端；没有可见终端时保持新建和收纳入口可用，不自动创建或关闭终端。
- 收纳后的终端仍保留运行状态、输出和通知。通过其他现有导航方式直接选中已收纳终端时，将其恢复到标签栏，避免选中的终端没有可见标签。
- 现有关闭操作继续作用于终端会话，关闭后清理对应的收纳记录。标签排序只影响可见标签，不改变收纳终端的相对顺序。

## 状态与边界

- 收纳属于可恢复的界面布局状态，随现有工作区会话持久化；它不作为终端运行状态或跨窗口实时同步状态。
- 用现有终端标识和工作区归属关系定位记录，恢复时兼容旧会话。终端不存在或已关闭时，不展示过期记录，也不能让后来复用相同位置的新终端继承过期状态。
- 复用终端目录及现有工作区导航，覆盖普通项目、普通和分离工作树、项目根目录、子工作区、分支工作区及其成员；恢复时保留正确的项目和工作区上下文。
- 保持紧凑布局与桌面布局均可访问收纳入口；三个点固定在工具栏右侧，不随标签横向滚动。

## 验证

- 覆盖收纳、恢复、全部收纳、关闭后清理、重启恢复和旧会话兼容。
- 覆盖不同工作区和工作树之间的列表归属及恢复导航，以及其他终端导航选中收纳项的行为。
- 检查右键菜单、固定入口、空列表、键盘操作、标签排序与紧凑布局。
- 运行 `bun run typecheck`、`bun run test` 和 `bun run check:architecture`。
