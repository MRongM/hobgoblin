# 子工作区标题栏动作与仓库依赖开关设计

**日期**：2026-07-30  
**状态**：已确认，授权内联自主实施

## 问题

主工作区仓库列表隐藏后，当前实现通过 React portal 把“新增子工作区”“批量拉取”和“显示工作区仓库”
迁移到底部状态栏。用户预期这三个动作属于子工作区列表上下文，应与子工作区刷新一起位于子工作区标题栏。

新建或扩展子工作区时，勾选一个仓库会立即读取并展开该仓库的未跟踪依赖项。依赖是可选能力，默认展开会
增加视觉噪声和不必要的预检请求，也缺少一个明确的“是否带入仓库依赖”意图。

## 目标

- 主工作区仓库列表隐藏后，将刷新、新增子工作区、批量拉取和显示工作区仓库都放在子工作区标题栏。
- 删除只为状态栏动作迁移存在的 portal 挂载连接。
- 手动刷新子工作区列表结束后，后台刷新一次所有已配置成员仓库的核心状态，使改动数量重新计算。
- 在每个可选仓库行的仓库名称与基准分支之间增加仓库依赖开关。
- 仓库依赖默认关闭；只有显式开启后才读取和显示依赖候选。
- 关闭依赖或取消仓库选择时，中止未完成读取并清空该仓库的依赖选择。

## 方案比较

### 采用：每仓库按需依赖开关

每个仓库独立表达是否需要依赖。开关关闭时既不读取也不提交依赖；开启时才读取当前基准分支对应来源。
该方案与仓库依赖本身的作用域一致，也与用户指定的仓库行中间位置一致。

### 不采用：一个全局依赖开关

全局开关无法表达不同仓库的不同依赖需求，并可能同时触发多个不必要的读取请求。

### 不采用：只折叠菜单但继续后台读取

该方案只改变外观，没有消除默认预检，也可能保留并提交不可见选择。

## 交互设计

### 子工作区标题栏

- 主工作区仓库可见时，现有主工作区标题栏动作保持不变；子工作区标题栏只显示刷新。
- 主工作区仓库隐藏时，子工作区标题栏按现有动作顺序显示：刷新、新增子工作区、批量拉取、显示工作区仓库。
- 状态栏不再承载任何工作区动作，也不再渲染工作区动作挂载点。
- 配置工作区与重新扫描仓库仍只属于可见的主工作区仓库标题栏。

### 手动刷新后的改动数量更新

- 手动刷新继续先读取权威子工作区列表，并保留现有防重复请求行为。
- 列表读取成功或失败并结束后，都对当前工作区每个已配置仓库调用一次现有 `refreshCoreData`。
- 成员仓库刷新在后台执行，不延长子工作区列表刷新按钮的 pending 状态。
- 一个成员刷新失败不会产生未处理 Promise，也不会阻止其他成员刷新；现有列表快照和错误展示保持不变。
- 自动漂移重读、弹窗依赖候选刷新和注册表清理后的重读不触发该附加刷新，避免把“手动刷新”语义扩散到其他调用点。

### 仓库依赖开关

- 仓库行使用三列布局：仓库选择、带“依赖”短标签的 Switch、基准分支。
- 仓库未选中、不可用、固定或操作进行中时，依赖开关不可用。
- 新建/扩展弹窗每次打开时，所有新仓库的依赖开关默认关闭。
- 勾选仓库只启用基准分支和依赖开关，不触发依赖读取。
- 开启依赖开关时，读取当前基准分支对应的依赖来源并展开现有依赖选择 UI。
- 开关开启期间切换基准分支，继续复用现有逻辑重新读取依赖并清空旧来源选择。
- 关闭依赖或取消仓库选择时，中止当前请求、清空读取快照与选择；再次开启时重新读取，所有候选回到“跳过”。
- 请求构造同时检查开关状态，关闭时绝不生成 `worktreeBootstrap`，即使 React 状态更新发生在同一事件周期。
- 工作区根目录级“子工作区依赖”保持现状；本开关只控制对应仓库的“仓库依赖”。

## 组件与状态

`WorkspaceRepositoryRail` 继续拥有工作区动作，只改变动作的渲染容器。`StatusBar` 和
`BranchWorkspacePane` 删除展示连接，不接管任何业务状态。

手动列表刷新在 `WorkspaceRepositoryRail` 内复用 `useReposStore.getState().refreshCoreData`。它读取当前
`workspaceProjects[rootId].repositoryIds`，因此每次点击只针对执行时仍配置的成员，不缓存过期成员列表。

`BranchWorkspaceDialog` 新增 `repositoryDependenciesEnabled: Record<string, boolean>` 作为弹窗局部状态。
该状态不持久化、不写入 Zustand、不跨窗口同步，也不改变服务端请求类型。现有
`repositoryBootstraps`、`repositoryBootstrapChoices` 与 AbortController 继续承担读取和候选选择职责。

```text
repository checkbox
  -> selected only

dependency switch on
  -> loadRepositoryBootstrap(repository, currentBase)
  -> render source picker / candidates

dependency switch off or repository unchecked
  -> abort in-flight read
  -> clear bootstrap snapshot and choices
  -> request omits worktreeBootstrap
```

## 错误与生命周期

- 依赖读取失败只在开关开启时显示现有错误；提示改为通过关闭后重新开启依赖开关重试。
- 弹窗关闭或重新打开时，现有 effect 继续中止控制器，并重置依赖开关、读取状态和选择。
- 不新增服务端 API、缓存、轮询、realtime 或持久化字段。
- 不改变分支工作区创建、扩展、预览、确认或审批语义。

## 测试

1. 工作区仓库隐藏后，四个动作都在子工作区标题栏，状态栏没有工作区动作挂载点。
2. 桌面与紧凑 scope 组合不再创建或重绑定状态栏动作 host。
3. 一次手动列表刷新结束后，每个已配置仓库恰好刷新一次核心状态，且后台工作不延长按钮 pending。
4. 仓库选中后依赖开关仍默认关闭，且不调用依赖预检。
5. 开启依赖开关后才读取并显示候选；开关位于仓库名称与基准分支之间。
6. 关闭依赖会中止请求、清空选择；重新开启重新读取且默认跳过。
7. 依赖关闭时切换基准分支不读取；开启时切换会读取新来源。
8. 现有依赖来源、批量选择、回退和提交测试显式开启依赖开关后继续通过。
9. 运行目标 Vitest、i18n 字典测试、类型检查、架构检查和完整测试套件。

## 非目标

- 不改变“子工作区依赖”区域的默认可见性。
- 不保存仓库依赖开关状态。
- 不修改仓库依赖候选的复制、软链接、来源回退或服务端校验。
- 不重排主工作区仓库可见时的标题栏动作。

## 工程原则

- **KISS / YAGNI**：删除不再需要的 portal 连接；开关保持为弹窗局部布尔映射。
- **DRY**：开启与基准分支变化继续复用 `loadRepositoryBootstrap`；关闭与取消选择复用同一清理函数。
- **SOLID**：Rail 负责动作归属，Dialog 负责短期交互，StatusBar 不再承担无关的工作区展示扩展点。

## 架构拷问结论

- 这是 renderer 展示与短期表单状态，符合 `docs/state-sync.md` 的 Local state 分类。
- 没有新增业务读写层，按 `docs/layering.md` 应保留在现有小型 UI 交互中。
- 状态栏 portal 是问题根因；删除它比增加条件分支更直接，也减少组件间耦合。
- “仓库依赖候选”与“子工作区依赖”已有明确领域定义，本次不新增领域术语，因此不修改 `CONTEXT.md`。
- 决策可逆、局部且不改变长期架构，不满足 ADR 条件。
