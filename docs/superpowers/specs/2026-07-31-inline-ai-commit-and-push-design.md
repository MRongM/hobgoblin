# 工作树内联 AI 提交并推送设计

**日期**：2026-07-31  
**状态**：已确认，授权内联自主实施

## 目标

在工作树的内联提交框中，于 `Codex` / `Claude` 生成按钮之前增加“生成后提交并推送”开关。开关开启后，点击任一 AI 生成按钮会按固定顺序完成：生成提交信息、使用生成结果提交当前工作树全部改动、触发现有分支推送动作。

## 已确认行为

- 开关每次打开提交框均默认关闭，不持久化，也不跨窗口同步。
- 开关仅在至少有一个 AI 提供方且当前分支具备推送能力时显示。
- 开启后，AI 生成结果直接替换提交框中的已有文本；显式开启开关即代表用户选择自动使用新结果，不再弹出“替换提交信息”确认框。
- 生成失败或返回空结果时不提交、不推送，提交框保持打开并显示原有生成错误。
- 提交失败时不推送，提交框保持打开，保留生成后的提交信息并显示提交错误。
- 提交成功后调用现有分支推送动作；普通分支直接推送，受保护分支继续使用现有推送确认，不绕过安全规则。
- 推送结果沿用现有分支动作的状态与通知，不新增第二套 Git 网络流程。

## 方案比较

### 采用：提交框编排、生成器返回成功结果

让 `InlineCommitDraftProvider.generateMessage()` 在继续维护现有草稿状态的同时返回 `string | null`。`InlineCommitForm` 在开关开启时用同一个单飞 pending 生命周期等待生成结果，随后调用已有 `onCommitAndPush`。

优点：变更集中在现有内联提交垂直切片中；生成、提交和推送复用现有边界；无需服务端协议；组件卸载时异步闭包仍能完成已启动流程，而 `useAsyncPending` 已具备卸载保护。

### 不采用：把提交和推送回调注入草稿 Provider

Provider 目前只拥有 AI 提交信息草稿与生成生命周期。注入 Git 写操作会把草稿状态容器变成通用工作流执行器，扩大职责并使测试依赖更复杂。

### 不采用：新增服务端“生成、提交、推送”组合 API

服务端组合接口会重复现有提交与分支推送写路径，还需要重新实现受保护分支确认、状态投影和网络结果通知。当前需求只是显式 UI 编排，不值得扩大协议面。

## UI 设计

复用 `src/web/components/ui/switch.tsx`。在提交信息标题行右侧的 AI 操作组内，依次排列：开关与短标签、`Codex`、`Claude`。标签使用 sentence case 对应文案“生成后提交并推送”。

开关沿用现有主题 token、尺寸与焦点样式，不引入新颜色、字体或动画。生成或提交期间禁用开关及 AI 按钮，防止同一工作流重复触发。开关不存在可用推送链路时不渲染，避免展示无法兑现的操作。

## 数据与控制流

1. 用户打开某一工作树提交框；开关局部状态为关闭。
2. 用户开启开关并点击可用的 AI 提供方。
3. 表单进入单飞 pending 状态并调用现有 `generateMessage`。
4. 生成器继续更新草稿状态，并向调用者返回生成文本；失败返回 `null`。
5. 成功时表单清除潜在替换确认、把生成文本写入草稿，然后调用现有 `onCommitAndPush`。
6. `onCommitAndPush` 先等待 `commitRepositoryChanges` 成功，再触发现有 `actions.push`。
7. 提交成功后关闭并清理草稿。推送确认、执行状态和结果继续由现有分支动作链路拥有。

## 状态归属

开关是一次提交框交互中的短期选择，属于 `docs/state-sync.md` 定义的 Local state，保留在 `InlineCommitForm` 的 React state 中。它不进入 Zustand、服务器设置或会话恢复。

提交信息草稿与生成生命周期继续由 `InlineCommitDraftProvider` 拥有。唯一契约扩展是生成动作返回成功文本，让调用表单可以串接已有写操作。

## 错误与竞态

- 开关状态在点击 AI 按钮时形成该次操作的意图快照；执行期间控件禁用。
- 生成请求被取消或失败时返回 `null`，自动链路立即停止。
- 自动模式下已有手工文本由生成结果替换；关闭自动模式时保留既有替换确认行为。
- 提交写入失败会被表单捕获并显示，不触发推送。
- 提交成功而推送失败时，提交已经存在且不回滚；这与现有“提交并推送”语义一致，推送错误由分支动作结果面呈现。
- 受保护分支推送仍可能在提交成功后要求确认；取消确认只阻止推送，不回滚提交。

## 测试与验收

1. 生成动作成功时向调用者返回生成文本，失败或取消时返回 `null`，原有草稿更新语义不变。
2. 有 AI 提供方和推送能力时显示开关，且 DOM 顺序位于 `Codex` 前；默认关闭。
3. 未开启时点击 AI 只生成文本，不提交、不推送。
4. 开启时点击 AI 使用生成文本调用一次“提交并推送”，成功后关闭提交框。
5. 自动模式覆盖旧文本且不显示替换确认。
6. 生成失败不提交；提交失败不推送并保留表单错误。
7. 无推送能力时不显示开关。
8. 四种语言字典完整且快照一致。
9. `bun run typecheck`、`bun run check:architecture`、目标测试与全量 `bun run test` 全部通过。

## 非目标

- 不保存开关偏好。
- 不自动选择 AI 提供方或在打开提交框时立即执行。
- 不改变 AI 提示词、模型、生成 API 或 Git 提交内容范围。
- 不合并提交和推送为服务端事务，也不回滚已成功的提交。
- 不绕过受保护分支确认、Git 并发控制或现有推送目标解析。

## 工程原则与架构拷问结论

- **KISS**：只扩展生成动作返回值，并在现有表单内串接已有提交推送回调。
- **YAGNI**：不增加设置、持久化、服务端 API、实时事件或新的 Git 抽象。
- **DRY**：提交、推送、错误通知与受保护分支规则全部复用现有链路。
- **SOLID**：草稿 Provider 仍只负责草稿/生成；表单负责用户交互编排；Git 写路径保持原责任。
- 状态归属符合 `docs/state-sync.md` 的 Local state 规则。
- UI 复用现有 shadcn/Radix primitive，符合 `docs/ui-conventions.md`。
- 渲染器只组合现有服务端边界，不新增跨层导入，符合 `docs/arch.md`、`docs/layering.md` 与 `docs/renderer-model.md`。
