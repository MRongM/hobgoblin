# 子工作区变更计数一致性设计

**日期**：2026-10-04

**执行方式**：用户授权自主决策、inline 执行，需用户确认的事项留到完成后。

## 已验证的问题

- Windows 原生 Git 返回 `C:/workspace/hob-feature/api`，Node 路径构造返回
  `C:\workspace\hob-feature\api`。子工作区根项、成员文件区和 Changes 总数使用字符串相等，
  两个成员分别有 2 和 3 个变更时，汇总得到 0；统一字符串后得到 5。
- 成员摘要通过分支的 Git 路径读取状态，因此可能显示正确数字，而根项不显示总数。
- 已发现成员带有权威 `repositoryId`，根项仍只从配置仓库名称解析 ID，可能读到另一个投影。
- 定时状态刷新默认 120 秒。子工作区及成员选择保持工作区根为 `activeId`，现有全局
  启发式刷新不能据此读取成员仓库。外部改动在没有新触发时等待下一轮轮询。
- 发现投影也用字符串相等检查成员工作树，Windows 等价路径会导致重复的 core-data 刷新。

## 方案与决策

| 方案                                                   | 收益                                   | 成本与选择                                        |
| ------------------------------------------------------ | -------------------------------------- | ------------------------------------------------- |
| 复用路径身份、统一计数选择器，并补充子工作区上下文刷新 | 修复漏计，导航和返回窗口可读取过期状态 | 采用；沿用现有 status 读取与请求协调              |
| 改写服务端返回路径或新增持久计数                       | 部分客户端比较可保持不变               | 不采用；会改变运行时契约并复制状态                |
| 降低全局轮询默认值或增加文件 watcher                   | 持续检测外部文件变化                   | 不采用；请求/平台成本扩大，不符合此次局部修复范围 |

### 计数与身份

在现有 `src/web/stores/repos/worktree-state.ts` 增加 `getWorktreeChangeCount(repo, path)`：

1. 用共享 `sameLocalFilePath` 匹配确切工作树的 status。
2. 有 status 时取 `entries.length`，包括权威零值。
3. 尚无该工作树的 status 时，使用同一路径的规范 worktree state 中已知 `changeCount`。
4. 未知数量返回 0，不把泛化 dirty 信号当作精确数量。

根项、成员文件区及 Changes 汇总共用该选择器。成员仓库优先使用服务端发现的
`repositoryId`，没有该字段时沿用配置成员名称映射。已移除和不可用成员不进入总数。
仅匹配词法路径身份；保留原始路径用于操作和显示。Windows 路径忽略分隔符与大小写差异，
POSIX/SSH/WSL Linux 路径仍区分大小写，不按分支名称替代路径身份。

### 刷新时机

增加上下文 hook `useBranchWorkspaceStatusRefresh(workspace, selectionKey)`：

- 进入子工作区、成员关系/可用仓库实例改变、切换成员时，读取过期成员 status。
- 打开根文件区或切换其 Git 面板/面板内成员时，执行同样的过期检查。
- 窗口重新获得焦点或文档重新可见时，执行同样的检查。
- 每次从最新 store 解析目标与实例 token，并按 repository ID 去重。
- 复用现有 10 秒启发式 TTL；缺少成功状态或时间戳也视为需要刷新。
- 不读取不可用、非 Git、已移除成员；不启动已经 loading/refreshing 的读取。
- 单仓读取失败不会阻止其他成员，卸载时移除事件监听。

刷新仍调用 `refreshStatus`，沿用服务端 Git、最新请求协调、取消、旧实例防护、错误保留语义。
定时刷新设置保持不变；持续留在终端且没有导航/焦点事件时，外部变化仍由配置轮询检测。
不把这次修复描述为文件事件实时监听。

## Grill 与架构审查结果

已使用全局 `grill-with-docs`、`grilling` 和 `domain-modeling` 指令检查设计。
用户已委托本次决策并指定 inline，事实调查和决策在本会话内完成。

| 决策分支     | 结论与依据                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------ |
| 领域边界     | 子工作区是配置工作区拥有的上下文；成员仍是独立 Git 边界（`CONTEXT.md`）                    |
| 状态所有权   | Git status 为服务端权威运行时数据；计数只是 renderer 派生（`docs/state-sync.md`）          |
| 刷新编排     | hook 调用既有 read action；UI 不执行 Git，不建立新 source 或持久计数（`docs/layering.md`） |
| Windows 身份 | 复用 `sameLocalFilePath`，不改变执行路径或 Git 环境                                        |
| 请求负载     | 10 秒 TTL、仓库去重、busy 过滤；保留配置轮询，避免新 watcher/定时器                        |
| 导航语义     | 刷新不改变 `activeId`、成员选择、文件区或终端归属（`docs/ui-conventions.md`）              |
| 跨窗口       | 沿用现有 server-backed 读取和 invalidation，不新增协议（`docs/realtime.md`）               |
| 失败与恢复   | 已成功成员更新，失败成员保留旧值；再次导航/聚焦或下一次轮询可重试                          |
| 兼容与隐私   | 使用通用路径/仓库名称；无新依赖；Node strip-only 合法 TypeScript                           |

不增加领域术语，不修改 `CONTEXT.md`。此决策局部且可逆，不建立 ADR。

## 验收

1. Windows 反斜杠清单与正斜杠 Git status 对应成员 2 + 3，根 badge 和 Changes 总数均为 5。
2. 大小写差异和 UNC 等价路径可匹配；POSIX 大小写不同及其他工作树不混入。
3. 成员的权威 repository ID 可计数；已移除和不可用成员排除；成功零值覆盖旧 snapshot 数量。
4. 新的上下文刷新只读取当前子工作区的合法成员，带最新 token，满足 TTL/busy/去重/卸载规则。
5. 进入/切换/聚焦可刷新过期数据，保持父上下文和配置轮询。
6. 等价 Windows 路径不会因发现投影而重复触发 core-data 刷新。
7. 针对性测试、`bun run typecheck`、`bun run check:architecture`、完整 `bun run test` 通过。
