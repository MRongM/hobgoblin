# 删除整个子工作区

用户明确要求：子工作区菜单“移除工作树”改为“删除工作区”；自动移除 worktree、删除独立仓库，最后删除文件夹及其全部剩余内容。只允许一次确认，不显示勾选项。

## 范围与交互

- 根项 More 与右键菜单统一提供危险操作“删除工作区”，替代根项的批量工作树移除。成员行仍可单独移除工作树，“从列表移除”仍只撤销登记。
- 使用一个确认框，展示确切路径和不可恢复的删除范围；确认后自动生成计划并提交计划要求的批准，不再逐项确认或勾选，也不额外删除外部仓库的本地/远程分支。
- 复用服务端 plan/execute/abort、文件夹操作锁和失效通知。服务端 remove 当前实际只是注销，必须恢复为真正的文件夹删除。
- 先移除文件夹内的关联 worktree，再删除独立仓库和剩余文件，最后删除文件夹并撤销登记。文件夹自身是 worktree 或仓库时也支持。
- 目录链接只移除链接；目录外的 Git 仓库或 worktree 不能成为物理删除目标。独立仓库仍有目录外 worktree 时阻止删除，避免破坏外部工作树的 Git 数据。

## 安全、取消与恢复

- 唯一一次确认覆盖目标文件夹内全部内容，包括未提交、忽略和未跟踪文件，以及独立仓库的本地 Git 历史；不把分支清理作为附加选择。
- 执行前重新验证计划及路径。内容变化导致计划过期时，在同一路径内自动重建一次并继续；路径发生变化则停止。
- 按用户补充要求，不扫描 dirty status、逐文件指纹或本地独有提交。只使用目录范围、Git worktree 身份/登记和既有互斥机制。
- 删除期间提供取消，沿用服务端 AbortSignal。已删除文件无法恢复；失败或取消保留登记与执行进度，重试继续处理尚存内容，不显示虚假成功。
- 成功后退出该子工作区选择并刷新结构、成员分支信息。所有测试仅操作独立临时目录。

## 验证

真实文件/Git 集成覆盖混合仓库与 worktree、根本身是 worktree、链接外部目录、计划过期及取消后重试。界面覆盖一次确认无 checkbox、自动审批、取消及错误保留。完成后执行类型、架构、全量测试，并与上一任务基线对照。
