# 文件夹式分支管理

**状态**：已按用户最新补充实现，待用户手动验证。

## 当前目标

Hobgoblin 登记文件夹的位置，并从实际文件系统和 Git 状态读取其中的仓库、工作树与当前分支。用户可以直接在外部添加、移除、重命名成员目录或切换分支，再在应用中刷新。

- 子工作区按文件夹名称显示，存放目录由用户自行输入或选择。
- 可以先创建或登记空文件夹，文件浏览和根目录终端立即可用。
- 完整仓库和 Git 工作树可以混用，成员不必同名，也不必使用同名分支。
- 不要求成员来自父工作区的配置仓库列表。
- 手动改变成员或分支属于正常操作，不产生需要修复的持久化成员漂移。
- 从列表移除只删除应用登记，不删除目录、Git 分支或终端。

## 保存与读取

持久化记录只保存文件夹位置，以及稳定 ID、父级分组和显示顺序所需的应用元数据。仓库成员清单、目标分支、来源、应用所有权和创建进度不是持久化约束。

旧版本登记保留 ID 和路径，按文件夹位置读取。刷新时重新发现实际 Git 仓库和工作树；移走的成员从列表消失，新添加的成员进入列表。文件夹本身不存在或不可读时显示不可用，用户可重新登记其位置。

读取仍由服务器负责，Renderer 展示服务器快照。注册、取消注册和可选 Git 写操作沿用现有失效通知，不新增后台轮询。

## 可选辅助功能

### 创建界面简化

创建子工作区使用左右分栏：左侧保留简化表单，依次填写文件夹名称和存放位置；右侧常驻创建详情，展示完整目标路径和操作步骤。窄屏时两栏上下排列。默认创建空文件夹时也展示详情；仓库/工作树和文件复制/链接分别作为可展开的选项。仓库同步按钮放入仓库选项，已选数量在收起时仍然可见。

名称、位置或选项每次变化后，右侧自动更新创建详情，无需再次点击预览或展开详情。执行计划继续由服务器检查，编辑后必须等待匹配当前输入的计划才能创建。检查状态、错误、必要确认和执行进度始终可见。保留已有文件夹登记入口及失败重试，不改变文件夹登记模型。

用户也可以通过应用创建空文件夹、添加工作树或克隆独立仓库。相关计划和进度只服务于当前操作，不能把一次创建时的成员或分支变成文件夹长期使用的前置条件。

应用继续遵守 Git 本身的限制：例如，同一仓库的一个分支通常不能同时被多个工作树检出。用户可选择独立完整仓库以获得独立的分支和 Git 数据。应用不强制统一分支名，也不移动或覆盖已经存在的目录。

选择成员后，可以使用原有的文件、终端和 Git 操作。切换分支以该成员的实际目录为目标，保留文件夹上下文；独立文件窗口按捕获的目录定位。

## 远程工作副本克隆

远程克隆是可选辅助功能。它在当前服务器可访问的本地目标目录建立副本，然后只登记新文件夹的位置。

- 保留所选成员的当前提交与分支、尚未推送的提交、暂存和未暂存修改、未跟踪文件及普通根目录文件。
- 忽略文件由用户选择是否带入。
- 默认创建独立完整仓库，也可明确映射到本地仓库的新工作树。
- 不复制远程 worktree 指针、hooks、凭据配置或共享对象指针。
- 不覆盖现有目录或引用；操作可取消，已完成成员保留，运行期间可重试剩余操作。
- 特殊 Git 状态、无法表达的链接或平台差异必须明确返回原因，不能丢失内容后报告成功。
- SSH/WSL 使用当前服务器的既有主机身份和认证；浏览器设备自己的文件系统不被当作服务器本地目录。

## 实施与验证方式

遵循用户最新要求：不自动暂存、提交、推送或改写历史；先实现功能，由用户手动验证。后续只运行必要的类型和架构检查，不继续自动浏览器验证、完整测试或审查循环。

手动验证重点：

1. 选择自定义位置，创建或登记空文件夹。
2. 手动往文件夹加入完整仓库和合法 Git 工作树，刷新后识别。
3. 各成员使用不同分支；手动切换后刷新，文件夹名称和上下文不变。
4. 手动移除一个成员，刷新后不再显示该成员，不要求修复或保留最后一个成员。
5. 在应用中从列表移除登记，磁盘目录和 Git 数据仍然存在。
6. 按需要验证远程克隆中的提交、暂存区、工作区和普通文件。

旧的严格成员清单、公共分支和管理所有权设计已由以上模型替代。
