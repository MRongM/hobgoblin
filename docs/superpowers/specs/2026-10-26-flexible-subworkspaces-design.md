# 文件夹式子工作区与混合仓库成员设计

**日期**：2026-10-26

**状态**：核心产品模型已确认；实现规格待审阅

## 用户已确认的目标

- 子工作区按文件夹名称创建和显示，使用文件夹图标。
- 文件夹名称和成员分支名称独立，各成员无需使用同名分支或同名工作树。
- 每个成员可选择使用独立完整仓库或 Git 工作树，同一个子工作区允许混用。
- 用户所说的“原始仓库”采用已确认的独立完整仓库含义，可从已有仓库或 Git 远程克隆。
- 在子工作区内直接切换各成员的分支，保持子工作区上下文。
- 将远程子工作区克隆到本地时，得到独立的本地工作副本。

## 具体使用场景

用户创建文件夹 `feature-set`，加入下列成员：

| 成员目录    | 使用方式                      | 初始分支      | Git 数据归属                       |
| ----------- | ----------------------------- | ------------- | ---------------------------------- |
| `service-a` | 工作树                        | `feat/auth`   | 父工作区已有的 `service-a` 仓库    |
| `service-b` | 独立完整仓库，从已有仓库克隆  | `fix/session` | `feature-set/service-b` 自己的仓库 |
| `service-c` | 独立完整仓库，从 Git URL 克隆 | 远程默认分支  | `feature-set/service-c` 自己的仓库 |

随后把 `service-b` 切到另一个已有分支，文件夹仍为 `feature-set`，成员仍为同一个成员，终端仍属于相同目录。`service-a` 的分支选择遵守所属仓库的工作树占用规则。

## 方案比较

| 方案                                               | 收益                                                           | 代价                                                     |
| -------------------------------------------------- | -------------------------------------------------------------- | -------------------------------------------------------- |
| 文件夹身份与显式成员类型，沿用现有子工作区生命周期 | 覆盖混合成员、独立分支和本地克隆；保留当前导航、终端和恢复机制 | 需要调整协议、持久化和按成员类型执行的生命周期           |
| 保留公共分支身份，增加显示名称和完整仓库入口       | 初始代码改动较少                                               | 创建去重和身份仍依赖公共分支，成员切换分支后语义容易冲突 |
| 统一重建整个 Project/Workspace 层级                | 可以进一步支持任意嵌套层级                                     | 涉及全局导航和项目恢复，范围超过当前目标                 |

采用第一种方案。创建、分支切换和克隆沿用服务器负责 Git 与文件操作的边界。

## 名称、身份与目录

- 用户填写“文件夹名称”，创建出的目录使用该名称，不再由分支名生成 `hob-` 前缀目录。
- 名称只允许安全的单级目录名；服务端根据目标主机校验路径分隔符、控制字符、保留名称和文件系统冲突。
- 同一父工作区内目录名唯一。重名时要求修改名称，禁止自动追加后缀后创建到意外位置。
- 子工作区使用独立稳定 ID，分支变化不会改变 ID。成员按子工作区 ID 与成员 ID 标识，目录名在当前子工作区内唯一。
- 已有记录保留原 ID、原路径、目录名和手动顺序；切换显示方式不会迁移磁盘目录或重建终端。
- 本轮保持现有对子工作区根目录的文件树结构保护；修改分支无需修改文件夹名。目录重命名和原地转换成员类型留作后续独立能力。

## 成员模型

每个成员记录以下概念，使用可区分的成员类型避免无效组合：

- 稳定成员 ID 与成员目录名称。
- 使用方式：独立完整仓库或工作树。
- 来源：已有仓库身份、Git URL，或者远程子工作区中的精确成员身份。
- 成员目录和实际执行 Git 的仓库身份。
- 应用管理的物化范围与创建进度。
- 创建时的分支选择及来源；当前分支从该成员目录的 Git 状态读取。

创建意图和当前分支分别保存或投影。用户切换分支后不把旧分支重新检出，也不把正常切换判为需要修复。

### 工作树成员

- 从同一主机上已有仓库创建 linked worktree，沿用现有工作树创建模式：已有分支、新建分支、跟踪远程分支或 detached HEAD。
- 每个成员独立选择分支、新建名称和创建来源。
- 分支已被同一仓库的其他工作树占用时，沿用现有阻止规则和可操作错误信息。
- 不移动或认领已经位于其他目录的工作树。
- 新增成员继续支持现有工作树依赖选择和创建前同步。

### 独立完整仓库成员

- 从已有仓库或 Git URL 克隆到成员目录，建立独立 Git 数据，禁止依赖源仓库的 alternates 或共享对象目录。
- 从已有仓库克隆时允许来源是 primary worktree 或 linked worktree，使用权威 Git 元数据确定源仓库。
- Git URL 克隆只获得 Git 可提供的已提交状态；来源工作目录的未提交状态只通过明确的工作副本复制路径带入。
- 从已有仓库创建时可独立选择目标分支；不要求源目录当前检出该分支。
- Git 远程配置沿用明确的源远程或输入 URL，不把临时导出地址误设为长期推送地址。
- 来源仓库保持原目录和当前分支；目标仓库的后续检出、提交和分支删除只影响目标仓库。
- 成员目录中的 primary worktree 是这个独立仓库的主工作目录，不调用 linked-worktree 删除命令删除它。

### 新增、扩充与成员类型

- 创建弹窗允许逐行选择成员、目录名、使用方式和分支；完整仓库行可输入 Git URL，工作树行选择已有仓库。
- 同一子工作区可以混用两种类型，同一来源也可通过不同成员目录建立不同工作副本。
- 默认仍使用工作树以延续现有创建方式；不自动把已存在的工作树转换为完整仓库。
- 扩充成员复用同一选择和计划流程，已完成成员保持原配置。
- 本轮不提供已有成员的原地类型转换；移除成员和按另一类型添加继续通过各自明确的生命周期操作完成。

## 列表、分支切换与现有操作

- 根项显示文件夹图标和实际目录名；成员行显示成员名称、类型、当前分支和现有改动/终端/同步状态。
- 成员行提供“切换分支”，复用普通仓库或工作树的已有切换流程和保护规则。
- 切换后只刷新目标仓库与当前子工作区快照，不离开子工作区、不重置成员展开状态或关闭终端。
- 终端会话按仓库与目录识别，不能用最初分支名标识成员。
- 批量提交、拉取、推送、合入、合出、刷新改动等动作根据成员实际仓库身份、目录和当前分支规划，禁止通过父工作区的同名仓库推断执行目标。
- 同一 Git 仓库的操作按仓库边界协调；独立仓库可以拥有相同分支名。需要锁定多个仓库的动作采用稳定顺序，避免交叉等待。
- fetch、pull、push 与 clone 保持可取消，同一仓库的并发网络请求复用既有协调边界；不因同一来源出现多行而无限启动网络进程。
- 聚合改动数量按实际成员工作目录计算，仓库级 fetch 等读取可按仓库身份去重。
- detached HEAD 成员显示提交信息，保留文件和终端体验；需要分支或 upstream 的动作明确禁用，继续复用现有 Git 能力约束。

## 发现、持久化与兼容

- 为持久化成员类型、来源、稳定身份和所有权升级子工作区 registry 到版本 2；版本 1 按既有工作树成员解释。
- 读取版本 1 时只在内存投影兼容，不在普通读取中执行迁移写入。首次明确写操作通过原子 registry 写入保存版本 2，并保留可恢复的版本 1 备份。
- 不认识的未来版本或无效记录保持显式错误，禁止按缺省类型推断后执行删除。
- 新注册目录按 manifest 中的精确路径发现，不再要求 `hob-` 等前缀。
- 原有带前缀目录继续发现；没有 manifest 的任意普通目录不自动成为子工作区。支持用户显式导入并预览目录内的 Git 成员。
- 已注册子工作区下直接发现的 primary repository 和 linked worktree 均可作为成员；通过 Git 元数据确认类型与所属仓库。
- 源父工作区仓库列表和子工作区成员列表独立。独立完整仓库无需出现在父工作区的仓库候选中。
- 成员从父工作区仓库配置移除或源目录不可用时，已独立克隆且可用的目标仓库继续正常工作。
- 旧的 `branch` 字段仅在版本 1 的兼容适配中提供创建来源，不能继续参与版本 2 的命名、去重或身份计算。
- 旧路径与稳定 ID 均不改变，已有排序、选择和目录终端恢复继续生效。

## 远程子工作区克隆到本地

远程子工作区复制与 Git URL 克隆是两条明确的来源路径。前者经已有 SSH 主机访问获取源工作副本，后者使用 Git 远程协议获得仓库内容。

### 目标结构

- 用户在远程子工作区菜单选择“克隆到本地”，选择本地父工作区和文件夹名称，并预览成员及其目标使用方式。
- 默认每个成员落地为独立完整仓库；用户也可为成员选择工作树并明确映射到一个本地已有仓库。
- 工作树模式导入源分支和提交到所选本地仓库，引用冲突时要求选择新名称，不覆盖已有本地分支；随后按正常 worktree 规则创建。
- 本地目标记录新的子工作区与成员身份。远程路径只作为来源，执行、终端和恢复均使用本地身份。
- 执行由目标本地服务器负责。浏览器连接远程服务器时，“本地”指目标服务器所在主机；只有存在可连接的本地目标服务时才提供跨主机克隆入口，不把浏览器下载冒充可直接使用的本地仓库。

### 工作副本内容

- 复制各成员的当前分支或 detached HEAD、当前提交及所需 Git 历史，包括源主机尚未推送的提交。
- 工作副本复制带回已暂存和未暂存修改、未跟踪且未被忽略的文件，以及子工作区根目录下的普通文件。
- Git 忽略文件通过预览中的显式附加选择决定是否复制，不默认复制依赖安装目录、缓存或构建产物。
- 来源包含 Git 冲突索引或进行中的特殊 Git 操作时，规划明确报告该成员无法完整复制的原因，执行前由用户处理源状态；不会静默生成看似完整的副本。
- Git 对象通过 bundle 或等价对象传输导入；差异使用二进制安全的暂存/工作区补丁与未跟踪文件清单恢复。
- 禁止直接复制指向远程机器的 `.git` worktree 指针、alternates、socket、终端会话、hooks 或用户级 Git 配置。
- 符号链接保持链接本身；源工作区内的绝对链接映射到对应目标路径。无法在目标平台表达的链接和工作区外链接在预览中作为阻塞项展示，由用户排除该项或选择复制其内容后重新规划。
- Git remote 保留明确的长期来源，临时 bundle 和导出路径不成为 upstream 或 origin。
- 源目录内容在采集期间变化时，停止受影响成员并要求重新预览，不自动执行修订后的计划；普通文件采集也校验文件清单与内容摘要。跨仓库的快照一致性按各成员分别校验。

### 进度、取消与恢复

- 沿用逐成员计划、执行、进度与恢复模型；克隆和传输有可取消的操作身份与超时。
- 成员先进入应用独占的临时目录，内容恢复并验证成功后发布到最终目录；绝不覆盖已有用户目录。
- 成功成员保留，失败成员可重试；只有已完成且当前可用成员参与后续 Git 操作。
- 重试检查源快照和目标所有权，不把不同来源或被用户修改的临时目录当作可续传数据。
- 取消后停止后续步骤，仅清理可确认归应用所有且未被外部修改的临时资源，保留成功结果与可解释的恢复状态。

## 移除、删除与修复

- 保留“移除成员”和“删除整个子工作区”的明确计划与执行入口。
- 工作树成员使用所属仓库的精确注册路径执行正常 worktree 删除，保留 primary/locked 等现有不可绕过边界。
- 独立完整仓库成员删除前展示精确目录、未提交改动和可能仅存在于此的本地提交，并要求明确确认；仅清理子工作区拥有的独立目标目录。
- 来源完整仓库、其远程分支，以及子工作区外的工作目录不属于独立成员删除范围。
- 删除整个子工作区时预览每种成员的清理方式；工作树分支清理沿用现有显式选项。完整仓库成员不会通过来源仓库的分支清理路径处理。
- 普通成员目录的物理结构变化继续表现为需要检查或修复，不能默默认领另一个仓库或重建用户已删除的数据。
- 不完整创建可从已有计划重试；已完成成员不回滚。修复独立仓库须有有效来源并再次预览，不能按旧分支名重新创建工作树。
- 移除选中成员后继续保留至少一个成员，删除最后一个成员仍使用整个子工作区删除流程，延续现有交互约束。

## 架构与状态边界

- `shared` 定义成员类型、来源、规划和快照的可区分协议。
- server read 负责目录、Git 身份和当前分支的权威投影；server write 负责模式分派、操作协调、取消和失效发布；source 负责 registry、文件系统与 Git/SSH 适配。
- routes 与 renderer client 只做协议解析和调用；Renderer 不执行 Git、下载仓库对象或自行构造文件清理范围。
- 创建表单、分支选择、克隆预览及瞬时 pending 保持 local 状态。
- 子工作区/成员快照和操作状态属于 server-owned runtime-coherent 状态；写入成功后沿用 WebSocket invalidation 与定向 refetch。
- 进度复用现有操作状态机制；本轮不新增周期轮询或独立同步流。
- 排序、当前选择与布局继续走既有 restorable 路径。
- Local、SSH 与 WSL 都走相同领域模型，路径和 Git 进程分别由实际主机适配器执行；WSL 使用原有 opaque identity。
- 本轮覆盖主应用 Desktop/Web 及其 Local、SSH、WSL 后端。Android 与独立 Windows 包保持已有产品范围，检查其消费的共享格式，不凭此次重构增加独立端完整子工作区 UI。
- UI 文案同时维护 en、zh、ja、ko，中文继续使用“子工作区”“工作树”，完整仓库选项使用“原始仓库（独立克隆）”。英文公开名称使用 Subworkspace；已有 `BranchWorkspace` 模块名可保留以减少无关迁移。

## 验收与测试

1. 创建任意安全名称的文件夹子工作区，名称无需满足 Git 分支命名规则，且不自动增加前缀。
2. 创建混合工作树/独立仓库的子工作区，两个成员使用不同分支并完成读写操作。
3. 同一来源仓库以不同目录贡献多个成员，按明确仓库身份和成员目录执行操作。
4. 在成员菜单切换本地或远程分支后，子工作区 ID、名称、选择与终端上下文保持稳定。
5. 独立仓库使用与来源相同的分支名时，其检出和提交不会改变源目录的当前分支或内容。
6. 工作树遇到被占用分支时保留 Git 限制并显示可操作错误；不自动移动已有工作树。
7. 独立仓库源目录不可用或从父级候选移除后，目标成员仍可正常使用。
8. 批量 Git 及手动改动刷新都使用成员实际身份和当前分支，聚合数量正确，成功与失败按成员返回。
9. 导入版本 1 保留原 ID/路径/排序，读取不写入；首次写入可恢复地升级，未知版本保持错误。
10. 发现任意已注册目录内的两类成员；旧前缀目录兼容；普通未注册目录不被自动认领。
11. 删除工作树与完整仓库分别调用正确清理路径；取消、重试、缺失来源、外部修改和锁定工作树均有覆盖。
12. 远程工作副本复制后，本地 Git 独立可用；保留未推送提交、暂存/未暂存改动、未跟踪文件和普通文件；忽略文件选择生效。
13. 远程克隆覆盖混合来源、本地工作树映射、分支冲突、链接处理、平台差异、源变化、超时和取消；远程源保持不变。
14. 回归文件预览、目录终端、成员 Git 面板、依赖、手动顺序和完整仓库作为单独项目打开时的共享目标状态。

测试使用临时 Git 仓库做来源与目标隔离验证，SSH/WSL 在进程适配边界使用通用测试 fixture。运行相关协议、source、plan、write、read、组件和四语言测试，再运行 `bun run typecheck`、`bun run check:architecture` 和完整 `bun run test`。

## 交付顺序

按相互依赖的纵向切片实现，整个目标均属于本次设计：

1. 文件夹身份、逐成员分支、兼容读取与工作树创建/切换闭环。
2. 独立完整仓库的创建、发现、Git 操作、移除与恢复，支持混合成员。
3. 远程子工作区到本地的完整工作副本复制与目标成员映射。
4. 跨切片回归、质量门、文档与已实施状态收尾。

每个切片完成其自身测试后再接入下一切片；前两个切片的代码不能假设第三个切片可以直接复制远程 worktree 指针。
