# 终端 Topbar 窗口拖拽统一设计

## 目标

在桌面端左右分栏布局中，不区分普通 Git 项目、普通文件夹项目或分支工作区，终端区 topbar 的非交互空白区域都能拖动 Electron 窗口。

## 当前问题

三个终端场景的窗口拖拽契约不一致：

- 普通 Git 项目始终将终端 topbar 标记为窗口拖拽区域。
- 普通文件夹项目仅在 `left-right` 布局中标记拖拽区域；该布局目前是唯一支持的桌面布局。
- 分支工作区仅在终端聚焦模式中标记拖拽区域，普通左右分栏模式缺少拖拽能力，并使用普通 toolbar 几何。

所有 `button` 和 `[data-interactive]` 元素均由全局样式标记为 `no-drag`。这是必要的交互边界：终端标签、关闭按钮和新建按钮必须保持可点击，窗口拖动只能从 topbar 的其余空白区域发起。

## 方案

沿用现有 Electron CSS 拖拽机制，在各终端面板组件中显式维持相同契约：

- 桌面左右分栏的终端 topbar 使用 topbar chrome 几何与色调。
- topbar 容器包含 `-webkit-app-region: drag`。
- 交互控件继续通过现有全局规则使用 `-webkit-app-region: no-drag`。
- 不把拖拽行为下沉到共享 `Toolbar`，避免文件区或其他普通 toolbar 意外成为窗口拖拽区域。
- 不新增专用组件；当前差异只需在现有调用点消除，避免过度抽象。

## 组件范围

- `BranchDetailToolbar`：保留现有桌面拖拽行为。
- `PlainWorkspaceTerminalPanel`：保留 `left-right` 桌面拖拽行为。
- `BranchWorkspaceTerminalPanel`：普通模式与聚焦模式均提供终端 topbar 拖拽能力；普通模式改用 topbar chrome 几何。

不修改移动端紧凑布局、终端标签交互、窗口主进程配置或其他工具栏。

## 验证

按测试驱动流程执行：

1. 在分支工作区终端面板测试中增加普通模式必须使用 topbar 高度并包含拖拽类的断言，确认测试先失败。
2. 对生产代码做单点修复，确认新增测试转绿。
3. 回归普通 Git 项目、普通文件夹项目和分支工作区的终端 topbar 测试。
4. 运行类型检查与架构边界检查。

## 验收标准

- 三类项目在桌面左右分栏下，终端 topbar 空白区域均可拖动窗口。
- 终端标签、关闭按钮、新建按钮及其他交互控件仍可正常点击。
- 分支工作区普通模式使用与应用横栏一致的 topbar 高度和色调。
- 移动端与非终端 toolbar 行为不变。
