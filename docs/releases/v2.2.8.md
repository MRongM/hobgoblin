Hobgoblin v2.2.8 corrects the Windows release boundary introduced by the independent platform package. The Windows x64 and ARM64 installers now package the primary root application from the same release commit as macOS, restoring features that were absent from the v2.2.7 Windows downloads.

## Highlights

- **Restore macOS and Windows feature parity:** Official Windows installers now contain the primary application's branch-prefix selection, recent-repository navigation, remote worktree branch switching, merge workflow, and shared notification behavior.
- **Build from one canonical desktop source:** macOS and Windows release jobs package the root `src/` application from the same workflow checkout instead of maintaining two release products with the same version number.
- **Validate both Windows architectures natively:** x64 and ARM64 installers run the packaged startup and internal-terminal smoke on their corresponding GitHub runners before publication.
- **Retain the independent package without release ambiguity:** The `windows/` package remains available for package-local development and testing, while its temporary CI artifacts are explicitly identified as independent and cannot enter the official Release.

## Linux Server Mode

`Hobgoblin-2.2.8-linux-source.tar.gz` contains the tracked Web/Server sources, configuration, licenses, and deployment scripts required for Linux Server Mode.

Install Node.js 24+ and Bun 1.3.11, then run:

```sh
tar -xzf Hobgoblin-2.2.8-linux-source.tar.gz
cd Hobgoblin-2.2.8
./scripts/serve-systemd.sh
```

Because the deployment archive does not contain Git metadata, use `./scripts/serve-systemd.sh update --no-pull` after replacing its files with a newer archive.

## Unsigned builds

The desktop builds and Android APK are unsigned.

- **macOS:** If Gatekeeper blocks the app, right-click it, choose **Open**, and confirm. You can also run `xattr -dr com.apple.quarantine /Applications/Hobgoblin.app` after installation.
- **Windows:** SmartScreen may warn about the installer. Continue only if you trust this GitHub Release source. WSL with a Unix-like terminal environment is recommended.
- **Android:** The APK must be signed before installation.
